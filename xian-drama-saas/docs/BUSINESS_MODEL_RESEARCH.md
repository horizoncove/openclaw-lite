## 0. 研究结论（先读）

### 0.1 一句话定性

> 这不是「Token 金融平台」，也不是「纯信息撮合站」。  
> 它是 **联盟担保下的 B2B 履约市场**：用 **适配保障** 解决找人，用 **托管结算（Tokens 积分）** 解决敢成交，用 **官方回收 / 法币合同** 解决供给方要现金——Tokens 只是结算与产能计量的**受控介质**。

### 0.2 逻辑自洽性总评

| 层面 | 评判 | 说明 |
|------|------|------|
| 价值主张 ↔ 产品核 | **自洽** | 适配×信任 ↔ 发布→确认→托管→放款 |
| Token 进/转/出 | **自洽** | 分桶 + 折价 + 禁互兑，挡住「买兑套利」主路径 |
| 飞轮主次 | **自洽** | A 主轮，B/C/D/R 卫星，避免五产品并列 |
| 收入与价值创造 | **基本自洽，有张力** | 购额加价依赖用量；撮合费依赖成交密度；若 A 冷、只卖 B，会退化成工具站 |
| 合规叙事 | **需持续谨慎** | 「积分/购额」可讲；一旦 UI/话术像币所，风险陡升 |
| 冷启动 | **最大执行风险** | 逻辑通，但双边密度靠运营，不靠功能堆叠 |

### 0.3 战略判断

**值得做**，条件是：

1. 联盟能提供真实供需冷启动（不是空广场）；  
2. 工程上 P0 必须落地托管放款，而不是长期停留在「需求广场 Demo」；  
3. 对外叙事永远是 **产业协作与履约担保**，不是 Token 升值。  

若做不到 1+2，Token 与回收越完整，越像空转金融外壳。

## 1. 逻辑全图重审（撮合 + Token）

### 1.1 对象分层（避免概念混淆）

| 概念 | 是什么 | 不是什么 |
|------|--------|----------|
| **撮合交易** | 能力时段的发现、确认、履约、结清 | 代币买卖 |
| **Match Order** | 承诺对象 + T 托管状态机 | 法币托管银行账户本身（可后接出纳） |
| **Token (T)** | 平台内积分：购额权 + 结算权 + 计量权 | 可流通货币 / 投资品 |
| **P_buy / P_redeem** | 官方目录购入价 / 官方回收价 | 外汇汇率、市场价格 |
| **C 环合同** | 法币项目制服务 | 钱包兑出的另一种按钮 |
| **账期** | 赊购 ¥ 应收 | 「把 T 卖回平台」 |

### 1.2 端到端因果链（研究用）

```
真实缺口（缺译者） 
  → 发布（适配）
  → 应征密度（供给是否驻留）
  → 确认（承诺成立）
  → 冻结 purchased/earned（信任抵押）
  → 履约可见
  → 放款 earned − fee
  → 供给：再投入 B/A  或  R 回收¥  或  接更多单
  → 需求：再发布
  → 平台：fee + 购额消耗毛利 +（可选）回收折价
```

任一环节断裂的商业含义：

| 断点 | 表面 | 商业实质 |
|------|------|----------|
| 无应征 | 广场空 | 无网络效应，会费难续 |
| 有应征无确认 | 需求方不回访 | 工作台/信任不足 |
| 确认无冻结 | 假订单 | 信任柱空心，供给不敢做 |
| 放款不到账 | 供给逃离 | A 密度坍塌，R 也无意义 |
| 无出口（无 R/C） | 人力供给拒接 T 单 | 只剩「自己也烧算力」的机构 |
| 出口过宽（互兑/购入可兑） | 黄牛进场 | 履约用户被挤出，品牌与合规双杀 |

### 1.3 Token 在撮合中的真实职责

Token 同时承担三角色，**必须分清优先级**：

1. **托管抵押物**（信任）——撮合核之所以用 T 而不是口头约定  
2. **产能计量单位**（B 环）——网关/算力同一账本  
3. **受控变现凭证**（R）——仅 earned 可销毁兑 ¥  

研究结论：若只能保留一个角色，保留 **① 托管抵押**；②③ 是增强。  
反过来说：把 ③ 做成主叙事（「来平台炒积分」）= 商业模式自杀。

## 2. 商业模式画布（联盟中枢版）

| 模块 | 内容 |
|------|------|
| **客户细分** | ① 需求方制片/发行机构 ② 供给方译制/配音/承制 ③ 要重交付的出海客户 ④ 联盟秘书处（治理用户） |
| **价值主张** | 比群更快找到对的人；谈妥有托管单据；工具用量一处算清；现金出口受控不靠黄牛 |
| **渠道** | 联盟会籍、秘书处运营、中枢 `/app`、服务中心进件回写 |
| **客户关系** | 机构账户 + 项目协作 + 仲裁担保；非 C 端增长黑客 |
| **收入流** | 购额加价、撮合费(T)、服务合同¥、会费、回收折价（次） |
| **核心资源** | 会员网络密度、信任规则、账本系统、上游模型/算力、秘书处组织能力 |
| **关键活动** | 冷启动撮合、托管结算、争议仲裁、计量运维、服务交付 |
| **重要伙伴** | 联盟、服务中心、模型供应商、对公支付/出纳 |
| **成本结构** | 研发、上游 API、运营/仲裁人力、支付与合规、回收备付金 |

**模式类型判断：**  
**多边平台（履约型）+ Usage Billing + 项目制服务** 的混合体；  
**不是** 广告模式，**不是** 交易所以费模式，**不是** 纯 SaaS 坐席模式。

## 3. 单位经济深挖

### 3.1 符号

- `T`：订单标价 Tokens  
- `f`：撮合费率（从 T 扣）  
- `P_buy`：购入官价（¥/T）  
- `P_redeem`：回收官价（¥/T），`ρ = P_redeem / P_buy ≤ 1`  
- `c_up`：B 环上游单位成本（折合 ¥/T）  
- `c_pay`：回收打款与运营单位成本  

### 3.2 三条路径的平台毛利（简化）

**路径 α：购额后全部在 B 环耗尽（不经撮合）**

```
毛利_α ≈ T × (P_buy − c_up)
```

稳、可预测，但**不创造联盟网络价值**；长期会变成「又一个 API 聚合器」。

**路径 β：购额 → 撮付供给 → 供给全部回收**

```
需求方成本 ≈ T × P_buy
供给方现金 ≈ (T − f·T) × P_redeem
平台毛利_β ≈ T×P_buy − (T−fT)×P_redeem − c_pay×… 
          ≈ T[ P_buy − (1−f)P_redeem ] − …
          = T[ P_buy(1 − (1−f)ρ) ] − …
```

例：`f=5%`，`ρ=0.92` →  
`1 − 0.95×0.92 = 1 − 0.874 = 0.126` → 大约 **12.6%×T×P_buy** 量级毛利空间（再扣支付/仲裁）。  
这是「履约撮合 + 受控兑出」下的核心价差逻辑：**折价 + 抽成**，不是买卖价差投机。

**路径 γ：购额 → 撮付 → 供给再投入 B/A（不回收）**

```
平台既拿撮合费对应价值，又可能在后续 B 消耗中再拿 Usage 毛利
```

对生态最健康：**T 留在体内循环**，回收备付压力小，网络密度升。

### 3.3 供给方体感（决定 A 能否转）

现金型供给的有效到手率：

```
到手率 ≈ (1−f) × ρ
例：0.95 × 0.92 = 87.4% 的「购入价标尺」
```

若再叠加开票税负与账期，体感可能掉到七成出头——**必须在商务话术里诚实**，并强调：

- 比「群里白干/拖欠」的预期损失仍可能更优；  
- 或引导走 **C 环法币合同**（定价含税、不经折价）。  

研究建议：对「纯人力、不耗平台算力」的品类，默认报价引导 **C 或较高明确定价的 A+回收**，避免供给误以为 1:1 提现。

### 3.4 需求方体感

需求方关心的不是 ρ，而是：

1. 能否更快找到人；  
2. 托管是否真挡风险；  
3. T 标价是否可折算进剧成本（项目成本视图）。  

因此 **P_buy 目录透明 + 项目成本汇总** 比「Token 金融感」更重要。

## 4. 激励相容与博弈点

### 4.1 三方激励矩阵

|  | 需求方 | 供给方 | 平台 |
|--|--------|--------|------|
| 希望 | 快、稳、价可控 | 有单、结得快、现金够用 | 成交密、消耗真、少套利 |
| 平台给的 | 广场+托管 | earned+R/C | 抽成+加价+折价 |
| 背叛策略 | 谈妥后改群结算 | 场外要现金、拒接 T 单 | 放开互兑吸血 |
| 防御 | 托管强制、工作台留痕 | 回收时效 SLA、C 旁路 | 分桶/禁兑/监督视角 |

### 4.2 关键博弈：场外结算

最危险均衡：平台只做「介绍人」，钱在微信走。  
则：无撮合费、无数据、无信任沉淀、会费空洞化。

**对策不是骂用户，而是提高「场内结算」的相对收益：**

- 托管降低纠纷成本（刚需）；  
- 场内订单进信誉（下单更容易）；  
- 秘书处仲裁只服务场内单；  
- 优质需求优先曝光场内履约好的供给。  

### 4.3 套利博弈

经典攻击：`购入 →（伪装成交）→ 回收`。  
现闸门：purchased 不可兑、冷却、月帽、对公、撮合费、争议审计。  

仍需警惕：

- 关联机构对敲刷单套回收；  
- 账期购额后立刻传导给关联供给兑出（信贷套利）。  

研究建议：P1.1 起对 **关联 org、异常快回收、低履约痕迹订单** 做监督队列规则（进监管视角）。

## 5. 与常见模式对比（定位）

| 模式 | 像什么 | 我们相同点 | 我们不同点 |
|------|--------|------------|------------|
| 分类信息站 | 58/群盘 | 有发布浏览 | 我们强制订单+托管 |
| 自由职业市场 | Upwork | 双边撮合 | 我们嵌联盟治理+产业品类；结算用积分闸门 |
| 支付托管 | 担保交易 | 信任柱 | 我们托管物是 T 积分，且接产能账本 |
| API 聚合 | OpenRouter 类 | Usage | 我们绑定产业履约网络 |
| 积分商城 | 航司里程 | 官方发行/回收 | 我们积分服务于 B2B 履约，不是 C 端兑换货架 |
| 加密交易所 | — | 表面都有 Token 字样 | **战略上必须远离**；无盘口无行情 |

**定位句（建议对外统一）：**

> 「联盟会员的履约协作与结算中枢；Tokens 是官方发行的工作积分，用于托管成交与工具计量，不支持转让交易。」

## 6. 结构性张力（研究必须直面）

### 张力 1：Token 便利 vs 认知成本

机构财务习惯 ¥ 合同；T 标价增加学习成本。  
**缓解：** 下单页并陈「参考 ¥（P_buy×T）」；对账单同时出 T 与 ¥；C 环保留纯 ¥。

### 张力 2：回收必要 vs 金融化嫌疑

没有回收，现金型供给不来；回收做得像提现盘，又像虚拟货币。  
**缓解：** 文案「官方结算/回购注销」；仅对公；折价；无行情；与购额分按钮。

### 张力 3：主轮 A vs 现金牛 B

B（购额 Usage）可能比 A 更好变现、更好演示。  
**风险：** 组织资源被 B 吸走，A 永远冷启动失败，联盟叙事破产。  
**治理：** OKR 以「托管放款笔数/再来率」为第一，Usage 为第二。

### 张力 4：C 环做大 vs 中枢心智

服务中心法币毛利高，易做成独立品牌站。  
**风险：** 用户只记出海站，不回中枢发单。  
**治理：** 进件必须挂项目；监督指标「中枢发起工单占比」。

### 张力 5：联盟公益属性 vs 平台抽成

抽成过高 → 场外；过低 → 不可持续。  
**建议区间研究：** 撮合费从低起步（如 3%–8%），用会费/购额补；对战略会员减免换密度。

## 7. 监管与合规视角（商业约束）

本模型有意选择：

- 不做法币资金池撮合盘口（订单用 T；C 走合同）；  
- 不做个人盘提现；  
- 强调企业会员与对公；  
- Token 定义为**预付工作积分 / 计量单位**。  

**仍建议法务专项确认：** 预收 ¥ 购额的资金管理、回收出金资质、发票与税项、是否触及支付/预付卡相关规定。  
产品侧原则：**功能别跑在法务结论前面**；UI 禁止币圈符号。

## 9. 逻辑体检清单（给产品/实现/商务）

每次改版问：

1. 这让「确认→托管→放款」更容易了吗？  
2. 是否新开了互兑/挂单/购入兑出缺口？  
3. 供给方下周还愿应征吗？现金出口是否仍诚实？  
4. 收入故事是否仍要求 A 有真实成交？  
5. 监管视角能否解释「钱与单」的异常？  

任一题答「否」→ 回炉。

## 10. 研究结论与建议优先级

### 坚持（已拍板，勿动摇）

1. 北极星：适配保障 × 信任保障  
2. Token：进/转/出 + 分桶 + 禁自由兑  
3. 主轮 A；B/C/D/R 为卫星  
4. 双出口：C 法币合同 + R 官方回收  

### 建议强化（研究增量）

| 优先级 | 建议 | 理由 |
|--------|------|------|
| P0 | 工程落地 match_orders 托管放款 | 否则商业模式未实证 |
| P0 | 商务话术去金融化，统一「工作积分」 | 降合规与认知风险 |
| P1 | 明确品类分流：人力现金型偏 C；工具密集偏 A+B | 提高激励相容 |
| P1 | 回收 SLA + 监督队列反对敲 | 守住供给与防套利 |
| P1 | 项目成本「T+参考¥」 | 降低需求方财务摩擦 |
| P2 | 撮合费分层/会员减免换密度 | 冷启动武器 |
| P2 | 法务备忘录专项 | 为扩量护航 |

### 最终判断

> **商业模式成立的充要条件，不是 Token 设计精巧，而是：联盟网络里持续发生「可信成交」。**  
> Token 与回收是让成交可结算、可留人的基础设施；把它们当成产品本身，模式必歪。
