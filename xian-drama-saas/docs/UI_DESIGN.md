## 0. 结论先说

参考稿的**主路径形状是对的**（购 Token → 发悬赏 → 大厅 → 交付验收），但品牌叙事、交互隐喻和信息架构与本产品**冲突**，不能照搬上线。

| 维度 | 参考稿（TaskMatch） | 本产品目标 UI（会员协作中枢） |
|------|---------------------|------------------------------|
| 产品定位 | Web3「去中心化 Token 市场」 | **机构会员协作中枢**：撮合适配 + 信任托管 |
| 登录 | Connect Wallet | **机构账号登录**（演示可切角色）；无链上钱包 |
| Token | TKC / 流通市值感 / 智能合约自动放款 | **平台积分 T**：官方购入；**平台托管冻结→验收放款** |
| 品类 | 开发 / 设计 / 写作 / 营销 | **微短剧履约品类**（译制、配音、发行…） |
| 主 CTA | 发任务 / 浏览任务 + Buy Token | **买额度 · 发悬赏 · 接单 · 验收**（角色分流） |
| 托管可视化 | 「Escrow/Lock → 智能合约 → 乙方收款」 | **客户确认供应商 → 冻结客户 T → 验收 → 平台付供应商** |
| 税务 | 无 | MVP 轻量：**购 T 开票入口**；结算单；兑 ¥ 后置 |
| 监督 | 无 | MVP 可弱化；全量见监督视图后置 |
| 首页预算 | 英雄区塞指标 + 双 CTA + 叙事 | **品牌 + 一句价值 + 一条主路径 CTA**；指标下沉 |

**设计北极星（与 C1.1 一致）**

> 用户第一眼应感到：**「找对人、谈妥有托管、做完能结清」**——不是「连钱包炒积分」。

## 1. 参考稿问题清单（须改）

### 1.1 叙事与合规风险

| # | 问题 | 为何必须改 | 目标改法 |
|---|------|------------|----------|
| U1 | 「Connect Wallet / 去中心化 / 智能合约」 | 产品禁止会员互转与挂单卖 T；非链上资产 | 改为「登录 / 机构认证」；文案用「平台托管」 |
| U2 | 「Token 流转 ¥2.6M+」类市值指标 | 易被理解成交易盘/二级市场 | 改为「本月成交订单数 / 托管中订单 / 活跃供应商」等履约指标 |
| U3 | 品类通用互联网外包 | 与微短剧会员场景脱节 | 品类标签绑定短剧履约类型 |
| U4 | 流程跳过「客户确认接单方」 | MVP 关键步：确认后才冻结 | 工作流必须画出 **应征 → 客户确认 → 冻结** |
| U5 | 「自动智能合约放款」 | 实际是平台账本 release；验收是人工/规则触发 | 文案：「验收通过后由平台结算至供应商钱包」 |
| U6 | 无发票/合同提示 | TAX-1.0：购 T 与开票绑定 | 购 T 页与钱包增加「发票申请 / 对公信息」轻入口 |
| U7 | 无角色分流 | 客户与供应商首页任务不同 | 登录后按角色进不同默认页 |
| U8 | 英雄区信息过载 | 违反「一屏一职」 | 营销首屏只留品牌 + 一句 + 主 CTA；流程与列表下沉 |

### 1.2 可保留的骨架

- 三步工作流区块（买 → 发 → 验收）→ **改成四步：买 → 发 → 确认托管 → 验收放款**
- 悬赏卡片网格（预算、标题、发布方、应征数）→ **保留结构，换字段与品类**
- Token 流转示意 → **改成「平台托管账本」竖向步骤，终点为供应商钱包，禁止链上图标**
- 页脚产品/支持/关于 → 可保留 IA，链到真实文档

## 2. 信息架构（MVP IA）

```
营销站（可选）
├── /                 价值主张 + 进入工作台
└── /how-it-works     四步托管说明（可选）

应用（必做）
├── /login            选演示角色 / 机构登录
├── /app              工作台（按角色卡片不同）
├── /app/wallet       余额分桶 + 购 T + 流水 + 开票入口
├── /app/bounties     悬赏大厅（供应商默认；客户可看）
├── /app/bounties/new 发布悬赏（客户）
├── /app/bounties/:id 详情：应征列表 / 确认 / 状态时间线
├── /app/orders       我的订单（托管中 / 进行中 / 已放款）
└── /app/orders/:id   订单详情：验收 / 放款结果 / 结算单
```

后置（不要出现在 MVP 主导航）：监督大盘、回收兑 ¥、出海、算力/网关、外发合集运营后台。

### 2.1 主导航（按角色）

| 角色 | 导航项 |
|------|--------|
| 客户 | 工作台 · 发悬赏 · 我的需求 · 我的订单 · 钱包 |
| 供应商 | 工作台 · 悬赏大厅 · 我的应征 · 我的订单 · 钱包 |
| 平台协助（可选） | 工作台 · 订单总览（只读列表） · （无完整监督大盘） |

右侧主按钮：

- 未登录：`登录`
- 已登录客户：`购买 Token`（实心）+ 余额摘要
- 已登录供应商：`悬赏大厅`（实心）+ 余额摘要  
- **禁止**：`Connect Wallet`、链上网络切换器

## 3. 关键页面规格（MVP）

### 3.1 营销首屏（若保留落地页）

**一屏预算（强制）**

- 品牌名：**会员协作中枢**（或对外正式名；勿用 TaskMatch / TKC）
- 一句价值：找对人履约，谈妥有托管，做完能结清
- 一句说明：客户购平台 Token 发悬赏；供应商接单交付；平台托管并结算（非链上资产）
- CTA：`进入工作台`（主） / `了解托管流程`（次）
- **禁止**首屏：Connect Wallet、市值类指标条、多枚浮动徽章、卡片式英雄图拼贴

指标与「最新悬赏」放在首屏**以下**第二、三屏。

### 3.2 工作台 `/app`

按角色展示**下一件该做的事**（不是通用仪表盘堆砌）：

| 角色 | 主卡片 |
|------|--------|
| 客户 | 余额不足 → 购 T；有待确认应征 → 去确认；有待验收订单 → 去验收 |
| 供应商 | 推荐/最新开放悬赏；进行中订单；待收款提示 |
| 平台 | 今日新发布数、托管中订单数（只读） |

### 3.3 购买 Token `/app/wallet`（购入区）

| 元素 | 要求 |
|------|------|
| 套餐或自定义金额 | ¥ → 预计到账 T（展示官方价） |
| 余额分桶只读 | 可用 / 冻结；MVP 可简化 purchased+earned 合并展示，细则见 D1.3 |
| 流水 | 购入、冻结、放款 |
| 开票 | 「申请发票 / 对公信息」入口（可先表单占位） |
| 文案 | 「向平台预付服务额度」；禁止「充值上链」「Gas」 |

### 3.4 发布悬赏 `/app/bounties/new`

必填：标题、描述、**品类**（短剧相关枚举）、预算 T、期限、验收标准（短文本）。  
提交后状态 `published`，进入大厅。  
余额不足时阻断并引导购 T。

### 3.5 悬赏大厅 `/app/bounties`

卡片字段（优化自参考稿）：

| 字段 | 说明 |
|------|------|
| 品类标签 | 译制 / 配音 / 发行 / 剪辑…（非开发设计写作） |
| 预算 | `1,200 T`（单位 **T**，不用 TKC） |
| 标题 + 摘要 | 一行标题 + 两行内摘要 |
| 发布机构 | 客户机构名（可无真人头像，用机构缩写） |
| 应征数 | `8 人应征` |
| 状态角标 | 开放 / 已选定 / 已关闭 |

列表筛选：品类、预算区间、仅看开放。

### 3.6 悬赏详情 + 应征

- 供应商：`应征`（可附短留言）
- 客户：应征列表 → **`确认合作`**（关键 CTA）
- 确认成功反馈：**「已冻结预算 xxx T，订单进入托管」**（必须可见，不可静默）

### 3.7 订单详情 + 验收放款

状态机展示（时间线，禁止合约哈希）：

```
已确认 → 托管冻结 → 履约中 → 验收通过 → 已放款至供应商
```

- 客户：`确认验收` → 成功页展示「平台已向供应商结算 xxx T（扣费若有）」
- 供应商：只读进度；到账后钱包闪提示
- 结算单：订单维度只读单据（金额、双方机构、时间）——对应 TAX 站内凭证

### 3.8 Token 流转示意（营销或钱包帮助）

竖向步骤（替换参考稿智能合约流）：

1. 客户购 T（官方）  
2. 发布悬赏  
3. 供应商应征 · 客户确认  
4. **平台冻结客户 T（托管）**  
5. 交付 · 客户验收  
6. **平台结算至供应商钱包**（高亮）

旁注一句：会员不可互转 T；结算仅经平台订单。

## 4. 视觉与文案约束

| 项 | 建议 |
|----|------|
| 主题 | 可用深色专业风；主色可用翠绿强调「放款/成功」，但避免 Web3 霓虹/发光堆叠 |
| 字体 | 中文用清晰无衬线；避免默认 Inter 堆营销腔 |
| 单位 | 一律 **T** 或「平台 Token」；禁止 TKC、ETH、Gas |
| 禁止文案 | 去中心化、上链、智能合约自动执行、Connect Wallet、二级市场、市值、流通盘 |
| 推荐文案 | 托管、冻结、验收、结算、官方购入、机构会员、撮合 |

动效（若做营销页）：2～3 处即可——例如步骤高亮推进、确认后冻结数字跳动、放款成功反馈；勿粒子链上特效。

## 6. 验收清单（设计 / 前端）

- [ ] 全站无「Connect Wallet / 智能合约 / TKC」字样与图标  
- [ ] 客户确认接单后有明确「已冻结」反馈  
- [ ] 悬赏品类为短剧履约类，非通用外包四件套  
- [ ] 供应商到账可在钱包流水核对  
- [ ] 购 T 区可见开票/对公入口（可占位）  
- [ ] 角色导航不同；供应商默认进大厅，客户默认可进「我的需求」  
- [ ] 营销首屏未堆指标条（指标在次屏）  
- [ ] 监督/回收/出海不出现在 MVP 主导航
