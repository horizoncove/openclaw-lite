## 0. 一句话

> 中枢不是功能仓库，而是让联盟里 **需求方、供给方、秘书处、专业服务、平台产能** 转起来的操作系统。  
> **使用功能**解决单次办事；**生态闭环**让「越用越好用、越多人越有价值」。

```
痛点(P1–P5) → 使用功能(可完成的动作) → 闭环(多方激励相容) → 飞轮(数据/信誉/产能沉淀)
```

## 1. 生态角色与交换物

| 角色 | 带进生态的东西 | 拿走的东西 | 若不参与会怎样 |
|------|----------------|------------|----------------|
| **需求方机构** | 项目、预算、期限、作品 | 合作方、进度可见、工具产能 | 仍靠群；匹配市场冷启动失败 |
| **供给方机构** | 译制/配音/承制等能力 | 订单、可预期结算、信誉 | 广场无应答；需求方流失 |
| **联盟秘书处** | 规则、担保、公告、仲裁 | 治理抓手、成交数据、会员粘性 | 信任靠私聊；规则被套利 |
| **专业服务中心** | 出海 SOP、发行资源、专员 | 工单量、服务收入、案例 | 中枢缺「重服务」出口 |
| **平台（网关/算力）** | 模型与队列产能 | Tokens 消耗、用量数据 | 中枢只剩协作 IM 化 |
| **会员个人执行者** | 时间与操作 | 待办清晰、少被催 | 系统有壳无人填状态 |

**生态成立条件：** 每一边都能在闭环里**重复获利**，且不能靠伤害另一边获益（故禁止 Token 转售）。

## 2. 使用功能地图（按用户动作）

功能按「用户完成一次有价值动作」定义，不按技术模块炫技。

### 2.1 经营操作系统（每日）

| 功能 | 用户动作 | 改变的原子 | 解的痛 |
|------|----------|------------|--------|
| F1 工作台 | 打开即看逾期/待确认/未读/作业/余额 | 注意 | P1 |
| F2 项目 | 建项目、改阶段 | 项目 | P1 |
| F3 任务 | 改状态、标阻塞、设截止 | 任务 | P1 |
| F4 通知 | 阅读、已读、跳转业务 | 注意 | P1 |

**使用闭环（个人）：** 注意 → 行动（改任务/确认应征）→ 状态更新 → 下次注意减少噪音。

### 2.2 匹配与履约（跨机构）

| 功能 | 用户动作 | 改变的原子 | 解的痛 |
|------|----------|------------|--------|
| F5 发布需求 | 填品类/条件/预算并发布 | 能力需求表达 | P2 |
| F6 广场浏览 | 筛选/打开需求 | 注意+发现 | P2 |
| F7 应征 | 留言并提交意向 | 承诺雏形 | P2 |
| F8 我应征的 | 跟踪是否被选 | 注意 | P2 |
| F9 确认成交 | 选定供给方 | 承诺成立 | P2/P3 |
| F10 撮合订单 | 看节点：托管/进行/放款/争议 | 承诺履约 | P3 |
| F11 秘书协助 | 标注/仲裁（P1） | 信任 | P3 |

**最小可用闭环：** F5→F6→F7→F9→F10。缺 F10 = 生态断在「认识了但交换没完成」。

### 2.3 产能获取（工具层）

| 功能 | 用户动作 | 改变的原子 | 解的痛 |
|------|----------|------------|--------|
| F12 官方购额 | 付钱获得 Tokens | 额度 | P3/P4 |
| F13 钱包流水 | 查充值/消耗/退款 | 注意+额度 | P3 |
| F14 API Key | 创建/轮换/复制 | 额度使用权 | P4 |
| F15 模型目录 | 选模型与价 | 注意 | P4 |
| F16 试调用/生产调用 | 调网关 | 额度消耗 | P4 |
| F17 算力作业 | 提交/取消/看状态 | 额度+任务结果 | P4 |
| F18 失败退款感知 | 见流水退回 | 信任 | P3/P4 |

**最小可用闭环：** F12→F16/F17→F13（花得明白）+ F18（败得明白）。

### 2.4 专业服务挂接（低频）

| 功能 | 用户动作 | 改变的原子 | 解的痛 |
|------|----------|------------|--------|
| F19 服务进件 | 从项目/介绍页申请出海等 | 能力（专业） | P5 |
| F20 服务工单 | 看评估/履约/验收进度 | 注意+承诺 | P5 |
| F21 回写项目 | 进度进入工作台/项目 | 项目状态 | P1/P5 |

**最小可用闭环：** F19→F20→F21。营销页单独存在但**不回写** = 生态断点。

### 2.5 治理与秩序（联盟侧）

| 功能 | 用户动作 | 作用 |
|------|----------|------|
| F22 公告发布 | 秘书处发通知 | 规则与机会触达 |
| F23 禁自由兑换 | 无互兑、无行情、购入不可兑 | 避开自由转化 |
| F24 订单托管放款 | 履约放 T 至 Earned | A 环 |
| F25 官方回收销毁 | Earned 销毁→对公退 ¥ | 供给方法币出口（受控） |

## 3. 四条生态主闭环

### 闭环 A · 协作匹配飞轮（最重要）

```
更多需求发布 → 供给方更愿驻留应征 → 成交/订单↑ → 信誉与案例↑
        ↑                                                      │
        └──────── 需求方更愿再发布 ← 履约可预期 ←───────────────┘
```

| 环节 | 使用功能 | 激励 |
|------|----------|------|
| 发布 | F5 | 比群喊更快找到人 |
| 应征 | F6–F8 | 比私聊更可跟踪 |
| 成交 | F9–F10 | 有单据、有节点 |
| 沉淀 | 订单历史/（P2）评分 | 降低下次信任成本 |

**断裂点：** 有广场无订单；应征无回音；只服务单边（只讨好需求方或只堆供给卡片）。  
**冷启动：** 秘书处代发/精选需求 + 首批供给机构运营答应对时响应。

### 闭环 B · 产能计量飞轮

```
官方购额 → 网关/作业被使用 → 账单清晰可信 → 继续购额
                │
                ├→ 用量数据反哺模型/队列运营
                └→ 绑定项目后形成单剧成本可见 → 负责人更愿统一采购
```

| 环节 | 使用功能 | 激励 |
|------|----------|------|
| 购额 | F12 | 一处买、团队共用 |
| 使用 | F16–F17 | 少开多控制台 |
| 信任 | F13、F18 | 敢用、敢预扣 |
| 沉淀 | usage / 作业记录 | 运营调价与扩容依据 |

**断裂点：** 失败静默扣费；转售破坏官方计量；Keys 混乱导致机构不敢开权限。  
**与闭环 A 的咬合：** 匹配成交后的履约（译制等）可**调用同一网关/作业**，把「找人」与「借机器」接在同一项目上。

### 闭环 C · 专业服务飞轮

```
项目需要出海能力 → 进件服务中心 → 工单履约 → 进度回写中枢
        ↑                                         │
        └──── 案例/口碑/复购 ← 验收结算 ←──────────┘
```

| 环节 | 使用功能 | 激励 |
|------|----------|------|
| 发现 | 服务介绍（可独立站） | 讲清 SOP |
| 进件 | F19 | 低摩擦提交 |
| 履约 | F20 | 专员有队列 |
| 回写 | F21 | 负责人不追问 |

**断裂点：** 服务站自称「唯一平台」带走日常心智；进度不回写；与 Tokens/订单体系无关导致数据孤岛。

### 闭环 D · 治理注意飞轮

```
规则/机会/告警 → 通知触达 → 已读与跳转行动 → 违规/逾期下降 → 治理成本下降
```

支撑 A/B/C：没有触达，匹配规则、余额告警、作业完成都变回群消息。

## 4. 总生态图（闭环如何咬合）

```
                 ┌──────────── 秘书处/治理(D) ────────────┐
                 │  通知·规则·禁转售·争议仲裁              │
                 └───────────────┬────────────────────────┘
                                 │
     ┌───────────────┐           │           ┌────────────────┐
     │ 需求方机构     │◄── A 匹配闭环 ──────►│ 供给方机构      │
     │ 项目·任务·发布 │      订单履约         │ 应征·交付      │
     └───────┬───────┘                       └────────┬───────┘
             │                                          │
             │         ┌────────────────────┐           │
             └────────►│ 会员中枢（主场）     │◄──────────┘
                       │ 工作台·状态·单据    │
                       └─────────┬──────────┘
                    ┌────────────┼────────────┐
                    ▼            ▼            ▼
              B 产能飞轮    C 服务飞轮     项目成本视图
              网关·作业·T   出海工单       （A+B+C 汇总）
```

**生态成功判据（用户可感）：**

1. 需求方愿意**反复**在中枢发布而非回群  
2. 供给方愿意**蹲**广场而非只接熟人  
3. Tokens **持续消耗且客诉扣费少**  
4. 出海工单**从中枢发起并回写**  
5. 秘书处通知**已读率**替代部分群公告

## 5. 使用旅程级闭环（端到端示例）

### 旅程 1 · 「一部戏从缺译者到交付」

1. 建项目/任务（F2/F3）→ 工作台可见截止（F1）  
2. 发布翻译需求（F5）→ 供给应征（F7）→ 确认（F9）→ 订单（F10）  
3. 履约中执行人用网关试译（F16）、提交批处理作业（F17）  
4. 作业成功通知（F4）；订单节点推进；必要时秘书仲裁（F11）  
5. 若需平台发行资源 → 出海进件（F19）→ 工单回写（F21）  

**闭环完成标志：** 同一 `projectId` 上能串起 需求、订单、用量、作业、工单。

### 旅程 2 · 「机构首次采纳工具额度」

1. 管理员购额（F12）→ 发 Key 给执行人（F14）  
2. 试调用见扣费（F16/F13）→ 信任建立  
3. 生产调用/作业成为习惯 → 再购额  
4. 负责人在项目维度看到工具成本 → 更倾向统一采购（飞轮）  

### 旅程 3 · 「反闭环：转售」

若允许机构间卖 Tokens：供给方/黄牛进场 → 官方定价失效 → 计量不可信 → B 飞轮停 → 连 A 的履约工具层一并受损。  
故 **F23 是生态基础设施，不是附属政策页。**

## 6. 构建生态的分期（与功能开开关联）

### 阶段 E0 · 单机可用（个人/单机构闭环）

- 开：F1–F4, F12–F18  
- 目标：自己机构内「看得见、用得成、账算清」  
- 尚未：跨机构飞轮  

### 阶段 E1 · 双边匹配闭环（生态成型关键）

- 开：F5–F10（+ F11 可简）  
- 目标：完整 A 闭环；冷启动靠秘书处运营  
- 验收：至少 N 次跨机构「发布→应征→订单」真发生  

### 阶段 E2 · 服务挂接

- 开：F19–F21  
- 目标：C 闭环；中枢心智不被服务站夺走  

### 阶段 E3 · 飞轮强化

- 信誉/评价、项目成本报表、用量驱动扩容、（可选）真实热度数据  
- 仍遵守：禁转售、双账户、中枢主场  

对应工程分期：E0≈现 P1 产能+工作台；E1≈V1.3 订单+我应征的；E2≈P1.1 工单；E3≈P2。

## 7. 生态健康指标（比「页数」重要）

| 指标 | 含义 | 健康方向 |
|------|------|----------|
| 跨机构订单数 / 活跃机构 | A 闭环是否转 | ↑ |
| 应征响应时长 | 供给是否活跃 | ↓ |
| 发布后 7 日成交率 | 匹配效率 | ↑ |
| Tokens 净消耗（剔测试） | B 闭环是否真用 | ↑ |
| 扣费争议工单 | 计量信任 | ↓ |
| 服务工单从中枢发起占比 | C 是否挂上 | ↑ |
| 通知已读率 | D 是否有效 | ↑ |
| 「该用哪个网站」咨询次数 | 心智是否分裂 | ↓ |

## 8. 设计禁区（会拆掉闭环的功能）

| 禁区 | 拆掉哪条环 |
|------|------------|
| Token 转售/挂单 | B + 治理 |
| 有匹配无订单 | A |
| 出海站替代中枢首页 | C + 心智 |
| 失败静默扣费 | B 信任 |
| 假热度当真数据 | 长期信任 |
| 功能堆满但工作台无行动信号 | 日常回访（A/B 入口枯竭） |

## 9. 对实现与演示的检查清单

做功能或演示页时自问：

1. 它改变了哪个原子状态？  
2. 它属于 A/B/C/D 哪条环的哪一环？  
3. 缺了它，环在哪里断？  
4. 它是否让某一边获得**不可持续**的好处（如套利）？  

若答不清，默认不进 MVP。
