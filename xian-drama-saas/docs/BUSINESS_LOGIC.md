## 0. 先分清三个「主体」（最容易混）

日常口语里的「服务中心」「平台」「联盟」不是同一个账本主体：

| 称呼 | 组织角色 | 对用户卖什么 | 主要收入形态 |
|------|----------|--------------|--------------|
| **西安微短剧产业联盟 / 秘书处** | 治理与撮合秩序 | 会员资格、规则、担保信任、公告 | 会费、担保/撮合服务费、活动 |
| **会员协作中枢（SaaS）** | 数字化操作系统 | 账号内的项目/需求/订单/通知 + **Tokens 产能** | SaaS 订阅（可后期）+ **官方 Tokens 购额加价** |
| **专业服务中心**（以**出海服务中心**为代表；可扩展审批/发行等） | 人力+资源型交付 | SOP 服务包（评估/译制/发行等） | **项目制/年框服务费** |

```
联盟（规则与信任）
   │ 授权运营 / 数据互通
   ├──────────► 会员中枢 SaaS（高频经营 + Tokens）
   │
   └──────────► 各专业服务中心（低频重交付）
                    └── 其中「出海服务中心」是当前最完整的一条专业线
```

**商业模式总原则：**

1. **中枢**靠「用得频」赚钱（额度与订阅），不靠倒卖会员间额度。  
2. **服务中心**靠「交付重」赚钱（人天/项目包），不靠再做一个第二 SaaS 收两遍软件费。  
3. **联盟**靠「秩序与担保」赚钱/获权，不靠与会员抢项目制利润（可抽撮合担保费）。  
4. 三条收入可以并存，但**用户心智只有一个日常入口：中枢**。

## 1. 生态闭环 ↔ 商业模式对照表

生态四环（见 ECOSYSTEM）与「钱从哪来」一一对应：

| 生态闭环 | 飞轮在转什么 | 谁付费 | 付给谁 | 计费对象 | 商业模式名称 |
|----------|--------------|--------|--------|----------|--------------|
| **A 匹配闭环** | 需求↔供给成交次数↑ | 需求方（主）/ 或双边 | 联盟结算账户（担保）→ 履约后给供给方；平台可抽**撮合/担保费** | **撮合订单**（合同金额，非法币进 Tokens） | **交易撮合 + 托管担保**（Marketplace take-rate / escrow fee） |
| **B 产能闭环** | Tokens 消耗↑ | 会员机构 | **中枢/平台官方**（统采模型与算力后加价零售） | **Tokens 钱包** | **预付费用量（Usage）**；可叠加 SaaS 席位费 |
| **C 服务闭环** | 工单交付次数↑ | 客户机构（常为需求方） | **出海等专业服务中心** | **服务工单 / 合同** | **项目制服务（Professional Services）**；可年框 |
| **D 治理闭环** | 规则触达与争议↓ | 会员（会费）/ 间接 | **联盟秘书处** | 会员资格、仲裁工时 | **会费 + 治理服务**；常为中枢与撮合的前提 |

### 1.1 一张钱流总图

```
会员机构 ──会费──► 联盟秘书处
    │
    ├──¥ 购 Tokens──► 中枢官方钱包 ──成本──► 模型商/算力商
    │                      │
    │                      └── 毛利 = 官方加价 - 上游成本 - 失败退款
    │
    ├──撮合订单金额──► 联盟托管账户 ──验收放款──► 供给方机构
    │                      │
    │                      └── 撮合/担保费（若收取）留联盟或中枢约定主体
    │
    └──服务合同款──► 出海服务中心 ──成本──► 译制团队/渠道/差旅等
                           │
                           └── 毛利 = 服务定价 - 交付成本
```

### 1.2 两种「钱」不可串账（商业上的硬隔离）

| | Tokens（B 环） | 订单/服务合同款（A/C 环） |
|--|----------------|---------------------------|
| 本质 | 预付的**平台产能使用权** | **人与人/机构交付**的价款 |
| 能不能机构互转 | **不能**（禁转售） | 按合同结算，可经托管 |
| 是否进钱包余额 | 是 | 否（进托管或对公合同） |
| 对应闭环 | B | A / C |

混账 = 商业模式自杀：要么变成黄牛盘，要么服务款被当成点数花掉。

## 2. 分层商业模式详解

### 2.1 联盟秘书处

| 项 | 内容 |
|----|------|
| 客户 | 会员机构 |
| 价值主张 | 可信撮合场 + 规则 + 担保与仲裁 |
| 收入 | ① 年费/会费 ② 撮合成交担保费（按单或按比例，可对 A 级减免） ③ 活动/培训 |
| 成本 | 秘书处人力、法务、托管账户成本 |
| 与中枢关系 | 中枢是其数字化手臂；通知/订单争议在中枢处理 |
| 与服务中心关系 | 可推荐会员使用服务中心；**不替代**服务中心报价 |

### 2.2 会员中枢 SaaS（主产品）

| 项 | 内容 |
|----|------|
| 客户 | 会员机构（管理员买单，执行人使用） |
| 价值主张 | 每日经营系统 + 统一模型/算力入口 |
| 收入（建议优先级） | **P0：Tokens 官方购额加价**（与 B 环绑定，立刻能转） · **P1：SaaS 席位/机构年费**（可与会费打包） · **P2：增值分析** |
| 不收 | Token 转售佣金；C 端硬币 |
| 成本 | 工程研发、上游 API/算力、客服、云资源 |
| 关键指标 | Tokens 净消耗、活跃机构、跨机构订单数（带 A 环） |

**中枢不靠「多做一个出海官网」赚钱**，靠机构把日常协作与工具消耗留在系统里。

### 2.3 专业服务中心（出海为代表）

见 §3 专章——这是「服务中心」业务逻辑的主体。

### 2.4 闭环与收入的依赖关系

| 若闭环不转 | 商业后果 |
|------------|----------|
| A 不转（匹配无成交） | 无撮合费；会费难续；中枢沦为工具站 |
| B 不转（没人买/不敢用 Tokens） | 中枢缺主现金流；只剩软件订阅难做厚 |
| C 不转（服务中心无工单） | 服务中心亏损或游离；中枢缺重交付故事 |
| D 不转（通知/规则失效） | A/B 信任崩，续费与购额双杀 |

**健康组合：** A 做厚信任与频次 → 拉动 B（履约要用工具）与 C（复杂单进服务中心）→ D 降低治理成本。

## 3. 出海服务中心 · 完整业务逻辑

以下把「服务中心」当作**可独立核算的专业服务事业部**，同时挂在中枢之下运营。

### 3.1 服务中心是什么 / 不是什么

| 是 | 不是 |
|----|------|
| 卖**可交付的出海能力**（评估、译制、发行协同等） | 不是会员日常 OS（那是中枢） |
| 客户成功靠**项目验收** | 不是 Tokens 零售商（可建议客户去中枢购额自用） |
| 进度应**回写中枢项目/工作台** | 不是第二个「唯一 SaaS」品牌抢登录入口 |
| 可对会员/非会员报价（价政策不同） | 不是 Token 市场或挂单撮合盘 |

### 3.2 客户分层与报价逻辑（业务侧）

沿用业界常见 A/B/C，与中枢会员等级可映射：

| 等级 | 谁 | 买什么 | 商务形态 | 与中枢关系 |
|------|----|--------|----------|------------|
| **C 单次** | 试水机构 | 单部评估/单语译制/单平台发行支持等 | 按项目报价（如「¥x 万起」） | 建议注册中枢看工单；可以仅进件 |
| **B 年度** | 有稳定产能的会员 | 年度服务包（N 部评估+译制档位+发行支持） | 年框 + 超额按次 | **强绑定中枢**：工单、项目、通知 |
| **A 战略** | 核心会员 | 定制全流程、专属团队、优先渠道 | 定制合同 + 驻场/优先 | 中枢内专属对接人；可减免撮合费等联盟权益 |

**升级路径（用户可理解）：** C 做完首单 → 抵扣升级 B → 合作满期可申 A。  
**原则：** 软件功能不按 A/B/C 阉割核心协作；**服务产能与响应级别**按 A/B/C 区分。

### 3.3 服务目录（卖什么）

与用户可感知的 SOP 对齐（名称可运营调整）：

| 服务编码 | 名称 | 客户要的结果 | 主要成本 | 典型周期 |
|----------|------|--------------|----------|----------|
| OS-EVAL | 剧本/项目出海评估 | 评估报告+市场建议 | 分析师+AI 辅助 | 约 1–2 周 |
| OS-ADAPT | 本地化改编 | 可拍/可译的改编稿 | 编剧 | 视体量 |
| OS-TRANS | 译制（字幕/配音协调） | 合格译制交付物 | 译者/配音+质检；可耗中枢 Tokens | 视集数 |
| OS-POST | 后期协同 | 母带/版本 | 后期团队 | 视项目 |
| OS-DIST | 发行上架协同 | 平台进度与材料 | 渠道经理+关系 | 视平台 |
| OS-DATA | 数据监测报告 | 周期报告与建议 | 分析 | 订阅式/按季 |
| OS-BIZ | 商业化/植入顾问 | 商务方案 | 商务 | 按需 |

客户可**单点购买**或**打包**（战略级全流程）。

### 3.4 端到端业务状态机（服务中心主链路）

```
线索/咨询
   → 进件（Intake）          ← 来源：中枢项目「申请服务」或服务站表单或秘书处转介
   → 评估（Evaluating）      ← 可否接、报价要素
   → 报价确认（Quoted）      ← 客户接受 SOW/合同
   → 履约中（In Delivery）   ← 可拆多个内部任务；可调用中枢网关/作业
   → 验收（Accepted）        ← 客户或约定验收人签字
   → 结算（Settled）         ← 开票回款
   → 关闭（Closed）
         ↘ 亦可在评估/报价阶段 Closed（未成交）
```

**每一状态都必须：**

1. 在服务中心侧可操作（专员工作台）  
2. 在会员中枢侧**只读可见**（客户不问群）  
3. 尽量挂 `projectId` / `orgId`  

### 3.5 服务中心内部角色

| 角色 | 职责 | 系统动作 |
|------|------|----------|
| 商务 | 线索、报价、合同 | 建进件、推报价状态 |
| 项目经理 | 履约排期、风险 | 改工单状态、拆任务 |
| 译制/发行执行 | 干活 | 回传交付物链接；可用中枢 Key |
| 质检 | 门禁 | 阻断验收 |
| 财务 | 结算 | 回款登记（可先线下） |
| 客户（会员） | 发起、催、验收 | 中枢看进度、确认验收 |

### 3.6 服务中心与中枢 / 匹配环的接口

| 场景 | 走哪条环 | 钱怎么走 |
|------|----------|----------|
| 客户只要「找一个自由译者」 | **A 匹配**（需求广场） | 订单托管给译者；服务中心可不下场 |
| 客户要「中心包干译制+发行」 | **C 服务** | 服务合同款给服务中心；中心可再外采译者（成本） |
| 客户自助用 AI 翻一版草稿 | **B 产能** | 只耗 Tokens；服务中心不收费 |
| 服务履约中用 AI | **C + B** | 服务费照收；Tokens 可由客户自备或计入服务成本（合同写明） |

**业务分流规则（给一线）：**

- 标准、可标准化、价格敏感 → 引导 **A 广场**  
- 要结果承诺、多环节、要渠道 → 进 **C 服务中心**  
- 仅工具 → **B**  

避免服务中心与广场抢同一单又不结算清楚。

### 3.7 服务中心收入、成本、毛利逻辑

```
收入 = Σ 项目合同额（C/B/A 价政策）
成本 = 直接人力 + 外采译制/配音 + 渠道费用 + （若代付）Tokens/算力 + 分摊管理
毛利 = 收入 - 成本
```

**定价注意：**

- AI 降低的是部分译制成本，不应在未测算前承诺「人工 1/5」为合同条款。  
- A 级低价换量时，要用年框保证利用率，避免专属团队闲置。  

### 3.8 服务中心的「小闭环」如何喂大生态

```
服务交付成功 → 案例与口碑 → 更多进件（C↑）
       │
       ├→ 客户留在中枢看工单 → 中枢日活（P1 缓解）
       ├→ 履约耗 Tokens → B↑
       └→ 部分环节发广场外包 → A↑（服务中心当「超级需求方」）
```

服务中心也可以是 **A 环的大买家**：把译制拆包发到联盟广场，自己做质检与总包——此时：

- 对客户：仍是 C 环合同（一个乙方：服务中心）  
- 对译者：是 A 环订单（甲方：服务中心机构账号）  
- 账上：客户款进服务中心；广场订单款从服务中心成本支出  

这是「总包 + 联盟产能」的标准结构，必须在合同与系统主体上写清。

## 4. 五条业务逻辑主线（端到端，含账本）

### 主线 L1 · 会员日常经营（中枢）

触发 → 登录中枢 → 工作台处理逾期/通知 → 更新任务。  
**收费：** 含在会费或 SaaS；无单笔。  
**闭环：** D + 个人效率（支撑 A/B）。

### 主线 L2 · 联盟撮合交易（A）

触发 → 发布需求 → 应征 → 确认 → **撮合订单** → 托管 → 验收 → 放款（扣担保费若有）。  
**收费：** 担保/撮合费（政策可配）。  
**禁：** 用 Tokens 当订单支付介质互转。

### 主线 L3 · 工具产能（B）

触发 → 购额 → Key → 调用/作业 → 流水；失败退款。  
**收费：** Tokens 加价。  
**禁：** 转售。

### 主线 L4 · 出海服务总包（C）

触发 → 进件 → 评估报价 → 合同 → 履约（可内做或转 A 外采）→ 验收结算 → 回写中枢。  
**收费：** 服务合同。  
**可选：** 合同约定 Tokens 谁出。

### 主线 L5 · 治理（D）

触发 → 秘书处公告/仲裁 → 已读/争议单关闭。  
**收费：** 会费摊薄；仲裁或加急可另计。

## 5. 「服务中心」对外叙事 vs 对内核算

| 对外（客户听得懂） | 对内（财务/系统） |
|--------------------|-------------------|
| 「一站式出海服务」 | C 环专业服务收入 |
| 「联盟会员中枢」 | SaaS + B 环 Tokens |
| 「联盟担保撮合」 | A 环订单 + 担保费 |
| 「统一 AI/算力」 | B 环，官方购额 |

对外可以有品牌伞「产业服务」，对内必须**分账本、分合同、分系统对象**（工单 / 订单 / 钱包）。

## 6. 商业模式选择建议（决策用）

| 阶段 | 主推现金牛 | 理由 |
|------|------------|------|
| 冷启动 | **C 服务项目** + **B Tokens** | 服务证明价值；Tokens 验证工具粘性 |
| 成型 | **A 撮合规模** + B 消耗 | 网络效应；中枢成为必经之路 |
| 稳定 | SaaS 年费打包会费 + A/B/C 组合 | 收入可预测 |

不建议第一天就靠纯 SaaS 订阅养活团队——除非会费已覆盖。

## 7. 业务逻辑检查清单（评审用）

每上一个功能/报价/演示页，问：

1. 它落在 L1–L5 哪条主线？  
2. 钱进 **会费 / Tokens / 撮合费 / 服务合同** 哪本账？  
3. 是否违反「Tokens≠订单款」？  
4. 服务中心是否又在抢中枢登录心智？  
5. 若服务中心外采广场运力，甲乙方主体是否在系统里正确？  

答不清 = 业务逻辑未梳清，不应上线话术。
