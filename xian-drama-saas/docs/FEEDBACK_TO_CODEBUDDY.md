## 0. 先定性：你们做对了什么、缺什么

| 判定 | 说明 |
|------|------|
| **站点类型** | 出海**专业服务营销落地页**（SOP 卖服务 + 定价 + FAQ），不是会员协作 SaaS |
| **与我方关系** | 对应 PRD「专业服务层 / 出海服务中心」——**正确分层**，不要改成「全站唯一产品」 |
| **优点** | 痛点→方案清晰；SOP-01～06 可讲清交付物；A/B/C 分级有商务逻辑；Hero 有控制台示意 |
| **主问题** | ① 把「服务中心」写成了「整个产业平台」② 控制台是死示意、无真实工作台入口 ③ 指标与案例难核实 ④ 与会员中枢 / API·算力 / 全联盟需求零连接 ⑤ 定价与 FAQ 轻微不一致 |

**总调：** 保留「出海服务营销」定位，**不要**学 MiniMax 做成撮合大盘，也**不要**宣称自己是产业唯一 SaaS；升级为「服务入口 + 可追踪工单 + 挂接会员项目」。

## 1. 定位与文案修改（P0）

### 1.1 标题层级（建议替换）

| 位置 | 现状 | 建议 |
|------|------|------|
| `<title>` / Logo | 一站式微短剧**全球化服务平台** | 陕西微短剧**出海服务中心** · 联盟专业服务 |
| Hero 主标题 | 让中国微短剧扬帆出海 | 可保留情感句，但副标题必须落到服务 |
| Hero 副文 | 一站式赋能全球化布局 | **会员项目可一键申请出海服务**；译制 / 制片 SOP / 发行 / 数据回写工作台 |
| 页脚 | 全球化服务平台 | 与联盟「会员协作中枢」并列的一条**专业服务线** |

首页增加一行产品关系（必加）：

> 本站为**出海专业服务**入口。项目管理、全联盟需求、API 聚合与算力调度见 **会员协作中枢（SaaS）**。[进入中枢 →]

### 1.2 明确「做什么 / 不做什么」

**做：** 剧本评估与改编、制片 SOP 管控、译制、平台发行、数据监测、商业化顾问；服务工单进度回写会员项目。  

**不做（写进 FAQ 或页脚小字）：**

- ❌ 不做 Token / 额度转售  
- ❌ 不替代会员自己的项目管理与全联盟需求广场  
- ❌ 不把「秦云算力」Logo 暗示为可倒卖算力商品（算力由中枢 **作业调度 + 钱包计量** 提供）

## 2. 信息架构优化

### 2.1 建议页面结构（单页也可按锚点重排）

```
1. Hero（品牌 + 一句话关系 + 双 CTA）
2. 服务对象与准入（联盟会员 / 非会员如何咨询）
3. 痛点三道坎 → 解决方案（保留，压缩空话）
4. 六大 SOP 服务（保留，每卡补「交付物 / 周期 / 回写到哪里」）
5. 服务如何在系统里跑（工单状态机 · 新增）
6. 控制台预览（可点击假数据或跳转真实 client 门户）
7. 分级定价 A/B/C（修一致性）
8. 可信证明（案例需可核验或降调）
9. FAQ + 咨询
```

### 2.2 双 CTA（替代单一「免费咨询」）

| CTA | 去向 | 文案建议 |
|-----|------|----------|
| 主 | 咨询表单 / mailto | 申请出海服务评估 |
| 次 | 会员中枢登录或 `/overseas/client` | 已是会员？查看我的出海工单 |
| 第三（可选） | 文档/案例 | 查看 SOP 与交付标准 |

Hero 右侧「控制台」示意：点击应进入 **客户门户示意** 或说明「演示数据」，禁止让人以为已登录真实系统。

## 3. 功能修改意见（相对当前静态页）

### 3.1 把「六大服务」改成可履约的服务目录

每张 SOP 卡片补齐字段（哪怕第一期写死在页上）：

| 字段 | 示例 |
|------|------|
| 服务编码 | `OS-TRANSLATE` / `OS-DISTRIBUTE` … |
| 交付物 | 译制母带、评估报告 PDF、发行排期表 |
| 标准周期 | 与 FAQ 对齐（勿一边 20 周 SOP、一边 8–12 周上线却不解释） |
| 依赖 | 是否需会员项目 ID |
| 系统回写 | 进度 %、里程碑、资产链接写回「我的项目」 |

### 3.2 新增：服务工单状态机（你们缺的核心）

与我方出海客户门户对齐，建议对外展示：

```
咨询/进件 → 评估中 → 报价确认 → 履约中 → 验收 → 结算/关闭
```

页面上用一条横向状态条 +「会员可在中枢查看同款进度」。  
这比再堆「护城河」文案更能证明你们是**可运营服务**，不是宣传册。

### 3.3 控制台模块对齐真实能力（示意也要诚实）

现状示意 Tab：项目概览 / 剧本管理 / 制片进度 / 发行数据 / 翻译任务。  

建议改为与工单一致的模块名，并标注数据来源：

| 建议 Tab | 说明 |
|----------|------|
| 我的进件 | 咨询与立项 |
| 服务工单 | 状态、负责人、SLA |
| 译制任务 | 语种、进度、审校轮次 |
| 发行排期 | 平台、地区、上线日 |
| 结算与报告 | 节点款、数据报告 |

指标「本月上线 12 部 / 海外收入 $24K」：若为虚构，标注 **「演示数据」**；若为真实，注明统计口径与周期。

### 3.4 与会员中枢的挂接（相对 MiniMax 的差异化）

MiniMax 走「撮合大盘」；你们应走「**服务履约**」：

- 会员在中枢项目页点击「申请出海服务」→ 进件到本服务中心  
- 本站咨询表单提交后 → 生成 `service_request`，在中枢工作台可见  
- 译制可调用中枢 **API 聚合 / 算力作业**（平台计量），页面只说「调用联盟统一网关」，不宣传独立 Token 盘  

### 3.5 定价区修正（P0 一致性）

| 问题 | 修改 |
|------|------|
| 正文写 A/C，中间有 B「¥38万/年」，FAQ 提 B 级升级 | 三档标题统一为 **A 战略 / B 年度 / C 单次**，顺序 C→B→A 或 A→B→C 固定一种 |
| 「最受欢迎」仅装饰 | 保留可以，但写清包含「5 部评估 / 3 平台」是否含拍摄执行还是仅咨询+译制发行 |
| CTA「立即开始」无表单 | 接到同一进件表：机构名、项目名、目标市场、语种、期望档位 |
| 与联盟会员价关系 | 增加一句：联盟会员可走中枢下单/工单；非会员仅咨询通道 |

### 3.6 信任与合规

- 客户证言「某头部公司」「$5万」：无授权则改为匿名聚合数据或删除具体金额  
- 「95% 准确率」「1/5 成本」：补测试集说明或改为「内部评测口径，可提供报告」  
- 合作 Logo（ReelShort 等）：确认商标使用授权；「秦云算力」放到「基础设施合作」并链到算力调度说明，避免像发行平台并列造成误解  
- 联系方式 `400` / `business@microdrama.cn`：确保可触达，或改为「演示站 · 请通过联盟秘书处预约」

## 4. 技术方案意见（此站为营销页时的最小工程）

### 4.1 现状

单页 HTML + CSS + 少量 JS；控制台为静态装饰；无后端。  
**可以**作为品牌页，但必须在页脚声明：

> 本页为服务介绍与演示示意；下单、进度、结算以会员中枢 / 服务工单系统为准。

### 4.2 建议演进（仍小于 MiniMax 那套大盘）

| 阶段 | 范围 |
|------|------|
| **M0（本周）** | 文案分层、演示数据标注、定价一致性、双 CTA、页脚关系声明 |
| **M1** | 进件表单 → API `POST /service_requests` 或邮件+表格；成功页展示工单号 |
| **M2** | 客户门户只读进度（对接已有 `/overseas/client` 或中枢项目关联） |
| **M3** | 与译制任务、发行节点、结算报表打通；可选调用统一网关做译制辅助 |

技术栈不必重做 6 层架构；**不要**在本页堆等保/多区域话术。

### 4.3 指标与埋点（若继续用腾讯 beacon）

补充业务事件：`cta_consult`、`cta_portal`、`pricing_select`、`form_submit`。  
去掉或收敛无说明的第三方 beacon（隐私政策需提及）。

## 5. 与 MiniMax 方案的分工（避免两家撞车）

| 能力 | CodeBuddy 本站 | MiniMax 展台 | 我方中枢 |
|------|----------------|--------------|----------|
| 营销/SOP 服务卖点 | **主责** | 弱 | 文档引用 |
| 译者/配音等撮合大盘 | 不做或仅「可转介」 | 可做供给网络 | 需求广场+成交 |
| 项目/进度/通知 | 只读回写展示 | 易缺失 | **主责** |
| API 聚合 + 算力作业 | 说明「调用联盟网关」 | 易做成商品挂单（需按我方意见改） | **主责** |
| Token 转售 | **禁止** | **禁止** | **禁止** |

一句话给双方：  
**CodeBuddy = 出海服务橱窗与进件；MiniMax = 供需撮合（需按反馈纠偏）；中枢 = 会员日常经营与计量调度。**

## 7. 验收标准（本站专用）

1. 访客 10 秒内能理解：**这是出海服务，不是唯一产业 SaaS**。  
2. 能从本站到达：**咨询进件** 或 **会员工单入口**（二选一可点通）。  
3. 定价三档与 FAQ 无矛盾。  
4. 所有大数字有「演示 / 口径」标注或可提供证明。  
5. 无 Token 转售、无机构间额度转让入口。  
6. 不宣称等保/多区域/已上线控制台后台（除非真有）。

## 8. 结语

该站作为**出海服务营销页**方向正确， complementary 于会员中枢；问题在于叙事越权、示意过真、与中枢脱节。  
按上文 P0/P1 改完后，即可与 MiniMax（撮合）和我方中枢（经营+计量）形成清晰三角，而不是三个「都叫出海 SaaS」的重复展台。
