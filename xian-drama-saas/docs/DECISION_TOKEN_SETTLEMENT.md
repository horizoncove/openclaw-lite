# 商业决策：Tokens 撮合结算 + 官方回收退法币（受控）

> 版本：**D1.2**  
> 日期：2026-07-25  
> 状态：**采纳**  
> 关联：[BUSINESS_LOGIC.md](./BUSINESS_LOGIC.md) · [PRD.md](./PRD.md)

---

## 0. 决策一句话

> 客户官方购 T（可账期）→ 订单托管付供应商 T → 供应商可 **耗于生产**，或将符合条件的 T **销毁回官方**，由官方按规则 **退回法币**。  
>  
> **仍然避开「自由转化」：**  
> 无会员互兑、无行情汇率、无随时市价提现；  
> 仅有 **官方双向闸门**：购额（¥→T）与 **回收销毁（T→¥，审批+折价+来源限制）**。

---

## 1. 问题：需要法币的供应商怎么办？

供应商赚到的是 T，但房租/工资/税费要 **¥**。若完全不能变现：

- 只适合「自己也要烧算力」的机构；  
- 纯人力供给方会退出 A 环。

**解法（采纳）：官方回收销毁（Official Burn & Refund）**

```
供应商申请回收 → 校验来源与额度 → T 销毁（不可再花）
        → 生成退款单 → 官方打 ¥ 到已认证对公账户
```

这是 **平台回购积分并注销**，不是兑换所，也不是会员间自由兑换。

---

## 2. 「自由转化」vs「官方回收」——必须分清

| | 自由转化（禁止） | 官方回收销毁（允许，受控） |
|--|------------------|----------------------------|
| 对手方 | 任意会员/场外 | **仅官方** |
| 价格 | 随行就市、议价 | **官方回收价**（运营公布，可≤购入官价） |
| 频率 | 随时想换就换 | 申请制、限额、冷却、可审批 |
| 余额去向 | 转给别人或提现盘 | **销毁**，总流通减少 |
| 目的 | 套利、投机 | 给真实履约供给方结算现金流 |

**红线不变：** 禁止挂单「我卖 T」；禁止点对点 ¥↔T；禁止展示浮动汇率 K 线。

---

## 3. 回收规则（防套利，避开自由兑换感）

### 3.1 只回收「可回收余额」

钱包分桶（实现必做）：

| 分桶 | 来源 | 可否回收成 ¥ |
|------|------|----------------|
| **Earned（赚取）** | 撮合订单放款入账 | ✅ 可申请回收 |
| **Purchased（购入）** | 官方购额/账期入账 | ❌ 不可回收（防「买 T 立刻退款」套现） |
| **Frozen** | 订单托管中 | ❌ |
| **Bonus** | 活动赠送 | ❌ 或另策（默认不可） |

消耗生产时：建议 **先扣 Purchased，再扣 Earned**（或可配置），避免蓄意囤 Earned 专兑。

### 3.2 回收价与折价（打破 1:1 自由兑）

- 购入官价：`P_buy`（¥ / 每单位 T，目录价）  
- 回收官价：`P_redeem ≤ P_buy`（例如 90%～95%，运营定）  
- **禁止**用户自定义价格；**禁止**按外部行情浮动  

折价目的：抑制「购入→转一圈→兑出」；覆盖支付与风控成本。

### 3.3 额度、冷却、主体

| 规则 | 建议 |
|------|------|
| 主体 | 仅企业会员对公账户；个人户默认关闭 |
| 资格 | 信用≥L1；无严重争议；完成对公认证 |
| 上限 | 按月回收帽（如不超过本月 Earned 的 x% 或绝对帽） |
| 冷却 | 订单放款后 T₀ 日（如 7 日）才可计入可回收 |
| 审批 | 超阈值人工审；小额自动 |
| 去向 | 仅打款至该 org 备案的对公账户 |
| 税务 | 由供应商自负开票/完税义务；平台提供结算凭证 |

### 3.4 状态机

```
redeem_requested
  → under_review（来源/限额/对公校验）
  → approved → burning（扣减并销毁 Earned T）
  → payout_pending → paid（¥ 已付） / payout_failed
  → rejected（退回申请，T 未扣）
```

账本类型：`earn_release`（订单放款）、`burn_redeem`（销毁）、`fiat_payout`（¥ 退回，记在法币出纳，不记成「汇率兑换」）。

## 4. 完整资金与积分流（含回收）

```
客户 ──¥──► 官方购额 ──► 客户 T(Purchased)
                              │ 下单冻结
                              ▼
                         托管池 ──验收──► 供应商 T(Earned)
                              │                │
                         撮合费(扣T)            ├── 耗生产（网关/算力/再下单）
                                              └── 官方回收销毁 ──¥──► 供应商对公账户
                                                       ▲
                                                       └── 回收价 P_redeem，非自由市价
```

平台收入结构：

1. 购额毛利（客户付 ¥，上游成本 + 未兑出沉淀）  
2. 撮合费（扣 T，最终或被消耗或进入回收池时按规则处理）  
3. 回收折价差（`P_buy` 体系下未兑满部分）  
4. C 环服务合同（纯法币，与回收无关）

---

## 5. 与信用账期的关系

| 机制 | 方向 | 是否兑换 |
|------|------|----------|
| 账期购额 | 先得 T，后付 ¥ 应收 | 否（赊购） |
| 官方回收 | 销毁 T，退 ¥ | **是，但仅官方受控回购** |

风控交叉：

- 存在逾期 ¥ 应收的机构：**禁止回收打款**（先抵债）。  
- 授信未结清时申请回收：可自动优先冲应收再付余款。

---

## 6. 供应商路径选择（给运营话术）

| 供应商类型 | 建议路径 |
|------------|----------|
| 自己也要 AI/算力 | 赚 T → **优先投入生产**（最省事） |
| 要部分现金 | 赚 T → 部分生产 + 部分 **官方回收** |
| 只要现金、不做平台生产 | 优先接 **C 环法币总包**；或接单后申请回收（受折价与限额） |
| 想套利倒 T | **走不通**（购入不可兑、折价、冷却、禁挂单） |

---

## 7. 禁止清单（仍然成立）

1. 会员间 ¥↔T 互换、场外收 T  
2. 挂单售 T、浮动汇率、兑换所 UI  
3. Purchased 桶直接兑出  
4. 回收打到非备案账户/个人私人卡（默认）  
5. 用户自定回收价  

---

## 8. 系统对象增量

```
wallet_buckets: purchased / earned / frozen / bonus
redeem_requests(id, org_id, amount_t, price_redeem, fiat_amount, status, ...)
redeem_payouts(id, request_id, bank_ref, paid_at, ...)
ledger: burn_redeem, fiat_payout_offset
```

验收：

1. 购入 T 申请回收 → **拒绝**  
2. 订单赚取 T，过冷却 → 申请回收 → T 销毁 → 对公收到 ¥（按 P_redeem）  
3. 无「市价兑换」页；无会员互兑  
4. 逾期机构回收被阻断或先冲应收  

---

## 9. 四环（D1.2）

| 环 | 含义 |
|----|------|
| A | T 托管撮合 |
| B | T 消耗生产 |
| C | 法币专业服务（现金主通道之一） |
| D | 信用 + **官方回收闸门** + 禁自由兑换 |
| **R 回收** | Earned T 销毁 → 官方退 ¥（受控出口） |
