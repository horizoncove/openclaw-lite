# 商业决策修正：Tokens 作为撮合结算介质（平台托管）

> 版本：**D1.0**  
> 日期：2026-07-25  
> 状态：**采纳为业务方向**（修正 V1.2/V1.3「订单不得用 Token 结算」）  
> 关联：[BUSINESS_LOGIC.md](./BUSINESS_LOGIC.md) · [ECOSYSTEM_AND_USAGE.md](./ECOSYSTEM_AND_USAGE.md) · [PRD.md](./PRD.md)

---

## 0. 决策一句话

> 商业客户用人民币（可含**信用账期**）向官方购买 Tokens → 在撮合订单里用 Tokens **支付供应商** → 供应商赚取 Tokens → 再投入网关/算力生产。  
> **仍然禁止**：挂单倒卖、自由议价转让、脱单 P2P 转账。  
> **只允许**：平台订单托管下的「服务结算型」Token 转移。

这不是「恢复 Token 黄牛市场」，而是把 A 环（匹配）与 B 环（产能）用**同一记账单位**焊成飞轮。

---

## 1. 相对旧决策改了什么

| 项 | V1.3 及以前 | **现决策 D1.0** |
|----|-------------|-----------------|
| Tokens 用途 | 仅官方购入 → 调模型/算力 | **购入 → 付撮合货款 → 供给方再用于生产**（也可自用网关） |
| 机构间 Token | 全面禁止 | **禁止自由转让**；**允许订单托管放款** |
| 撮合结算 | 法币托管账户 | **默认 Tokens 托管结算**（大额/战略单可并行法币合同，见 §5） |
| 购额 | 现款 | **按信用等级**：现款 / 账期 / 授信额度 |
| 「转售」定义 | 一切互转都算 | **收窄为**：无订单的挂单、溢价倒卖、提现套利 |

## 2. 闭环如何转（客户语言）

```
① 商业客户按信用政策获得 Tokens（付现或账期入账）
        │
        ▼
② 发布需求 / 确认应征 → 生成撮合订单（标价以 Tokens）
        │
        ▼
③ 平台从客户钱包【冻结/托管】对应 Tokens（非直接给对方）
        │
        ▼
④ 供应商履约 → 验收通过
        │
        ▼
⑤ 平台【放款】Tokens 入供应商钱包（可扣撮合费）
        │
        ▼
⑥ 供应商用 Tokens：调网关 / 交算力作业 /（再作为需求方发单）
        │
        ▼
⑦ 官方持续售卖 Tokens + 上游模型成本 → 平台毛利
```

**飞轮：** 客户为找人买 T → 供给方赚 T → 供给方为生产花 T → 官方再卖 T / 抽撮合费。  
生态闭环 **A 与 B 合并为一条货币环**，不再靠「法币订单 + Token 饭卡」双轨解释。

## 3. 角色与激励

| 角色 | 付钱/付 T | 收钱/收 T | 激励 |
|------|-----------|-----------|------|
| 商业客户（需求方） | ¥（或账期）买 T；下单冻 T | 得到交付物 | 一账本搞定找人+工具 |
| 供应商 | 用赚到的 T 再生产 | 订单放款得 T | 收入可直接投产，减少换汇/另充 |
| 平台/中枢 | 上游 API 成本 | ¥ 购额加价 + 订单撮合费（T 或 ¥） | 用量与成交双收入 |
| 联盟 | — | 会费；或分成撮合费 | 秩序与担保 |
| 服务中心 | 可收法币服务费；也可收 T（政策定） | 项目制 | 总包时也可当需求方花 T 外采 |

## 4. 信用等级与购额 / 结算方式

### 4.1 信用等级（示例，可运营调整）

| 等级 | 典型对象 | 购额方式 | 账期/授信 | 风控 |
|------|----------|----------|-----------|------|
| L0 观察 | 新入住/非会员 | 仅预付现款 | 无 | 限额购、限额冻 |
| L1 标准会员 | 普通会员 | 预付为主 | 短账期可选（如月结、授信帽） | 逾期降级、停新冻 |
| L2 良好 | 成交稳定、无争议 | 预付 + 账期 | 较长账期 / 更高授信 | 动态调额 |
| L3 战略（≈A 级） | 核心机构 | 授信额度内先用后付 | 合同账期 | 合同担保、专人对账 |

### 4.2 账本上要分开的三种「T」

| 类型 | 含义 | 能否用于下单冻结 | 能否用于调网关 |
|------|------|------------------|----------------|
| **可用余额** | 已到账、未冻结 | 能 | 能 |
| **托管冻结** | 已下单未验收 | 否 | 否 |
| **授信已用** | 账期额度占用 | 视政策（通常先形成应收，入账后再冻） | 同左 |

**账期本质：** 客户对平台的 **人民币应收账款**；平台按政策先贷记 Tokens 或允许透支帽。  
逾期 → 冻结下单与调用 → 降级；**不得**把未结清授信再转给其他机构。

### 4.3 购额订单状态

```
申请购额 → (现款)待支付 / (账期)待授信审批
        → 已入账（Tokens + 到可用余额）
        → 已对账关单 / 逾期催收
```

## 5. 撮合订单（Token 结算）状态机

```
draft
  → pending_escrow     待冻结（余额不足则失败或走授信）
  → escrowed           已冻结客户 T
  → in_delivery        履约中
  → accepted           验收通过
  → released           放款至供应商（扣平台费后）
  → disputed           争议（秘书处）
  → refunded/cancelled 解冻退回客户
  → closed
```

**规则：**

1. 冻结必须成功才算成交生效。  
2. 放款只进供应商**平台钱包**，不出现「随便转给第三方」。  
3. 平台撮合费从冻结额中扣（或另计）。  
4. 超大额/涉实景拍摄等，可附加**法币合同**作法律兜底，系统内仍以 T 记账履约。

## 6. 与「转售」的边界（合规话术）

| 允许 | 禁止 |
|------|------|
| 因**有订单号**的验收放款而增加供应商余额 | 无订单的会员互转 |
| 供应商把赚来的 T 用于官方目录内消费 | 挂单「出售 Tokens」、溢价撮合 T |
| 账期购额（对平台负债） | 把授信额度拆给关联公司套现 |
| 订单争议下的平台调账 | 私下协商改余额无审计 |

对外一句话：

> Tokens 是联盟产业网络内的**生产与结算积分**；只能官方获取或订单赚取，不能场外买卖。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 变成类货币/投机 | 禁挂单、禁提现为法币（或严格兑出闸门后期再开）、用途限定 |
| 账期坏账 | 授信审批、保证金、逾期停权、与会籍挂钩 |
| 供给方囤 T 不用 | 可设活跃消耗激励；生产刚需（网关）自然消耗 |
| 定价混乱（服务标 T、工具也标 T） | 统一官价目录；订单标价审核 |
| 与旧文档冲突 | 以本文 D1.0 为准修订 BUSINESS_LOGIC / PRD 拍板条 |

```
org_credit_profiles(org_id, level, credit_limit_cny, terms, status)
token_purchase_orders(..., pay_method: prepaid|net30|..., credit_draw)
match_orders(..., price_tokens, escrow_tokens, fee_tokens, status)

```

验收增量：

1. 客户购 T（现款）→ 下单冻 T → 验收放款到供应商 → 供应商调网关扣 T。  
2. 信用客户账期入账 → 同样走冻结/放款；逾期不可新冻。  
3. 无订单互转接口 404/禁用。  
4. 挂单转售 UI 不存在。

## 9. 对生态四环的重写（摘要）

| 环 | 新含义 |
|----|--------|
| A | 匹配成交用 **T 托管结算** |
| B | 生产消耗 T；T 来源=官方购入 **或订单收入** |
| C | 服务中心仍可以法币总包；总包外采走 A（花 T） |
| D | 信用等级、账期、争议仲裁、禁挂单 |
