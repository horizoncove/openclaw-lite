# 商业决策修正：Tokens 作为撮合结算介质（平台托管）

> 版本：**D1.1**  
> 日期：2026-07-25  
> 状态：**采纳为业务方向**  
> 关联：[BUSINESS_LOGIC.md](./BUSINESS_LOGIC.md) · [ECOSYSTEM_AND_USAGE.md](./ECOSYSTEM_AND_USAGE.md) · [PRD.md](./PRD.md)

---

## 0. 决策一句话

> 商业客户用人民币（可含**信用账期**）向官方**单向购入** Tokens → 撮合订单里用 Tokens 支付供应商 → 供应商赚取 Tokens → **只用于**网关/算力/再下单等平台内生产。  
>  
> **硬禁：Token 与货币的自由兑换。**  
> - 禁止 T→¥ 提现/兑出/赎回  
> - 禁止会员间「用钱买别人的 T / 用 T 换现金」  
> - 禁止把官价当成双向汇率盘  
>  
> **仍禁：** 挂单倒卖、无订单 P2P 转 T。  
> **只允：** 官方购额（¥→T 单向）+ 订单托管放款（T 在账户间因履约转移）+ 平台内消耗。

---

## 0.1 最高约束：避开 Token↔货币自由转化

| 方向 | 是否允许 | 说明 |
|------|----------|------|
| **¥ → T（官方购额）** | ✅ 仅官方通道 | 现款或账期；价格为**目录官价**（运营定价），不是市场化汇率 |
| **T → ¥（兑出/提现）** | ❌ **永久禁止（产品默认）** | 任何「把余额换成人民币打到对公账户」的能力不做 |
| **¥ ↔ T 会员互换** | ❌ 禁止 | 场外或站内点对点兑换均禁止 |
| **T ↔ T 订单放款** | ✅ 仅托管订单 | 验收后由平台记账，不属于「兑换货币」 |
| **账期** | ✅ | 是「赊购 T 形成 ¥ 应收」，**不是** T 兑回 ¥ |

**定性（对外/对内统一）：**

> Tokens 是**平台内生产与履约积分**，不是可兑付法币的电子货币，不开兑换所，不提供赎回。

供应商若需要**法币收入**，走 **C 环服务合同**（对公人民币结算），或线下合同；**不得**指望把赚到的 T 在平台兑成现金。

## 2. 闭环（客户语言）

```
① 客户按信用政策【单向】购得 T（付 ¥ 或账期欠 ¥）
        │
        ▼
② 撮合下单 → 冻结客户 T
        │
        ▼
③ 验收 → 放款 T 至供应商钱包
        │
        ▼
④ 供应商【只】把 T 用于：网关 / 算力 / 再发单
        │
        ▼
⑤ 不存在第⑤步「供应商把 T 兑成 ¥」
```

需要现金的供给：接 **服务中心法币总包** 或自签法币合同；与积分环隔离。

---

## 3. 角色与激励（在无兑出前提下）

| 角色 | 激励（不靠兑出现金） |
|------|----------------------|
| 商业客户 | 一笔购额同时覆盖「找人结算 + 自用工具」 |
| 供应商 | 赚 T = 降低自己再生产的现金支出；累积产能权利 |
| 平台 | ¥ 购额收入（单向）+ 撮合费（扣 T）+ 上游成本差 |
| 必须法币收入的团队 | 走 C 环/法币合同，不进 T 兑出 |

若某类供应商「只想换钱、从不消耗 T」——产品上**不承诺**为其提供兑出；商务上引导法币通道，避免积分被当成工资账户。

---

## 4. 信用等级与购额（账期 ≠ 兑出）

账期/授信 = 客户欠平台的 **人民币货款**，平台贷记 T。  
结清的是 **¥ 应收账款**，绝不等于「把 T 卖回给平台」。

| 等级 | 购额 | 账期 | 风控 |
|------|------|------|------|
| L0 | 仅预付 ¥→T | 无 | 限额 |
| L1 | 预付为主 | 短账期可选 | 逾期停权 |
| L2 | 预付+账期 | 更高授信 | 动态调额 |
| L3 | 授信内先用后付 | 合同账期 | 担保+对账 |

分户：`available` / `frozen` / `credit_used`。

---

## 5. 撮合订单状态机（不变）

`pending_escrow → escrowed → in_delivery → accepted → released`  
争议 `disputed`；取消 `refunded`（T 解冻回客户，**仍不是兑 ¥**）。

法律兜底合同若用人民币表述义务，**系统履约记账仍用 T**；合同人民币条款不打开 T→¥ 通道。

---

## 6. 禁止清单（实现与演示必须为零）

1. 提现 / 赎回 / 兑付 / withdraw / redeem / cash-out API 与按钮  
2. 「T 市价」「浮动汇率」「今日行情」类 UI  
3. 会员发布「卖 T / 收 T 换现金」  
4. 无订单的 T 转账  
5. 把撮合费「结算成人民币打给个人」却从 T 余额直接折现（撮合费以**扣 T** 或**另开 ¥ 账单**，不得 T 折现打款）  

官方购额官价展示允许写成「参考：1 万 T = ¥x（购入价）」——**仅购入标价**，禁止「可按此价卖回」。

---

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 被认定为可兑付代币 | 产品与协议写明积分属性；无兑出；用途限定生产/履约 |
| 供应商不愿接单 | 法币 C 环并行；或接单方本身是需要算力的机构 |
| 账期被理解成兑出 | 对账单据只显示「购额应收 ¥」，不显示「T 回购」 |
| 演示误做兑换页 | 验收红线：搜 cash/withdraw/兑 必须为空 |

---

## 8. 系统与验收增量

对象同 D1.0；**额外：**

- 不存在 `POST /wallet/redeem` 及同类  
- 账本 `type` 不得出现「兑出」  
- 自动化：尝试兑出 → 404/403  

人工验收：

1. 购 T→冻 T→放款 T→供应商耗 T 调网关 ✓  
2. 全站无兑出入口 ✓  
3. 账期逾期停权，且催收单据为 ¥ 应收 ✓  

---

## 9. 四环摘要（D1.1）

| 环 | 含义 |
|----|------|
| A | T 托管结算撮合（积分转移，非法币兑换） |
| B | T 消耗于生产；来源=购入或订单收入 |
| C | **法币**专业服务（现金出口在这里，不在钱包兑出） |
| D | 信用账期、禁兑出、禁挂单、禁无单互转 |
