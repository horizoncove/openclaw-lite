## 2. 功能优化意见（按优先级）

### P0 — 上会前必须改

#### 2.1 信息架构减肥（防再次「大而全」）

侧栏现状分组过多。建议 **会员端默认只保留 P0**：

```
工作台
全联盟需求（广场 / 我发布的 / 我应征的）
项目任务
撮合订单
机构钱包
模型网关
算力作业
通知
机构/个人设置
—— 专业服务（折叠）——
海外译制（链到服务进件，不复制整站）
```

**移出默认导航或标「展望 / 非本演示验收」：**

- 企业存储（可做驾驶舱一个指标，不做独立大模块）  
- 审核备案（属中心服务，链到五中心/服务工单即可）  
- **版权区块链**（易变成概念炒作；无司法材料勿写「100% 司法采信」）  
- 「创作者中心」与「会员中枢」角色重叠：要么改成「成员工作台别名」，要么删除入口  

#### 2.2 计量单位统一（致命一致性）

页内同时出现：

- 钱包余额 **¥48,420**  
- API 按 **¥/1K tokens** 扣人民币  
- 我方契约是 **机构 Token 余额** + 官方套餐购买  

优化二选一（推荐 A）：

| 方案 | 做法 |
|------|------|
| **A. 额度制（推荐，对齐中枢）** | 余额显示 `Tokens`；购额套餐「¥xxx → N tokens」；流水用 token；人民币只出现在「购额订单实付」 |
| B. 法币钱包 | 全站改成预付人民币账户，并改写我方 ARCH——**不推荐**，与已拍板「官方套餐充额度」冲突 |

试调用成功文案需与单位一致；禁止流水出现 **余额为负**（见下）。

#### 2.3 演示数据自洽

当前流水样例存在明显穿帮：

- `07-23 16:42` 后余额出现 **¥-1,562**  
- 次日又跳回 ¥48,xxx  

审核观感：计费引擎不可信。  

要求：

1. 流水按时间重算，余额单调可追溯  
2. 至少 1 条「失败作业自动退款」前后余额正确  
3. 至少 1 条逾期任务 `dueAt < today`（已有，保留）  
4. 需求状态用词与状态机统一：`招募中` → 建议映射为 `已发布/对接中`，与文档 `published/matching/deal/closed` 对照表放页脚  

#### 2.4 需求广场语义清理

| 问题 | 优化 |
|------|------|
| 「出售:古装悬疑剧本」 | IP 授权/转让需求可以，但标题避免纯「出售」电商感；类型用 `IP授权`；成交走订单而非钱包转余额 |
| 「展示中」状态 | 不在我方状态机内 → 改为 `published` 或下架为内容橱窗（非需求） |
| 缺「我应征的」 | 导航或 Tab 补上 |
| 应征按钮 | 演示需能点出：留言 → 进入 pending → 发布方确认 → 生成订单（哪怕全是前端状态机） |

#### 2.5 安全文案 vs 演示暴露

文案写「Key 明文仅创建展示一次 · 只存 key_hash」，同时表格长期展示 `sk-prod-9X4f` 前缀并暗示可撤销——可以。  

但 curl 示例不要贴「完整可抄 Key」；公网页增加：

- 演示 Key 每次「一键登录」可轮换的假前缀  
- 重申：`/reset` 类能力若存在必须鉴权（对接真 API 时）  

### P1 — 下一轮体验质量

#### 2.6 主路径可点通（5 步脚本）

请在页内或旁路 README 给出「3 分钟脚本」，并保证按钮真改 localStorage：

1. 一键登录  
2. 发布一条全联盟需求（可见于广场）  
3. 切换演示乙方账号应征（需支持多角色切换，不能只有王晓东）  
4. 甲方确认 → 生成撮合订单  
5. 钱包试调用 → 余额降 → 流水多一条；再提交算力作业 → failed 见退款  

缺 **多角色切换** 时，撮合闭环无法自证。

#### 2.7 工作台

- 「分账待确认 / 转码中」偏发行运维，可留 1 条，但不要压过「逾期任务 / 待确认应征 / 进行中作业」  
- 增加：待确认应征数、未读通知、余额不足告警（若余额 &lt; 阈值）  

#### 2.8 模型网关

- 模型列表区分 `chat / translate / tts / embedding`（已有雏形）  
- 试调用默认走 chat；翻译模型不要混在同一「chat/completions」示意而不加注  
- 402 示例 JSON 的 `code` 与我方 `INSUFFICIENT_BALANCE` 对齐（大小写/命名统一）  

#### 2.9 算力作业

- 列表已较好；补：**取消 queued 释放预扣** 的一条示例行  
- Worker 名可保留；注明 Phase 1 可为「运维人工推进」  
- 成功后应有「回写项目/通知」一条（驾驶舱或通知中心可见）  

#### 2.10 出海专业线

- 译制订单表可保留，但 CTA 应为「从项目申请出海服务 / 查看服务工单」  
- 勿在本页再造完整 CodeBuddy 营销站；用链出去  

#### 2.11 通知中心

- 已有跳转钱包示例 → 推广到：跳转需求、订单、作业  
- `forceRead` 不做阻断即可，与我方决议一致

## 3. 技术方案优化意见

### 3.1 演示架构目标态（仍分两栏）

```
[当前] 单页 HTML + localStorage 状态机
[下一里程碑] 同 UI 壳对接：
   /api/v1/*  (项目/需求/订单/钱包/作业/通知)
   /v1/chat/completions  (真扣费或沙箱钥匙)
```

对接后页头声明改为：

> 演示环境 · 连接联盟沙箱 API · 非生产数据  

删掉「仅 localStorage」或降为 fallback。

### 3.2 状态机与我方契约对齐表（请贴进演示「规则」抽屉）

| 领域 | 演示用词 | 契约枚举 |
|------|----------|----------|
| 需求 | 招募中/展示中/已成交 | `published` / （删展示中）/ `deal` |
| 订单 | 已托管/进行中/已放款/争议中 | 建议：`escrowed|in_progress|released|disputed|closed` |
| 作业 | 已有英文机 | 保持与 ARCH 一致 |
| 购额 | 处理中/已到账 | `token_orders.pending|paid` |

### 3.3 不要做的技术承诺

- 页内「AWS S3 · 西安」「联盟链 BSN」并列：无部署证据则改「对象存储（规划）」「存证（规划）」  
- 「司法采信 100%」删除或改为「按存证服务商说明」
