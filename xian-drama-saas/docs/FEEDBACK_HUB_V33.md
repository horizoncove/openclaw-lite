## 2. 仍建议优化的点

### P0（对外讲解前）

1. **人工跑通「3 分钟脚本」并录像/截图**  
   发布 → 切李娜应征 → 切回确认 → 订单 → 试调用扣 T → 作业 failed 退款。  
   若任一步只改 DOM 不改存储，理事会现场会穿帮。

2. **分清两套「钱」**  
   - Tokens：购额/网关/算力/存储计量  
   - 撮合订单「已托管/已放款」：更像**法币或结算托管**  
   页内应用脚注写清：*订单托管金额可与 Tokens 报价并存，但放款走秘书处结算账户，不从机构 Token 余额互转。*  
   否则「禁止余额转让」与「订单放款」会被问成逻辑矛盾。

3. **热度测试模块降调**  
   已有「前端模拟、非真实平台数据」声明——好。但侧栏标「新」+ 驾驶舱强入口，容易抢主路径。  
   建议：默认收进「专业服务 / 洞察（实验）」；驾驶舱卡片改为次级；对外口称 **实验功能**，勿进 MVP 验收。

4. **版权链 / 审核备案**  
   已标展望/工单——保留折叠默认收起；首页不要出「已确权 5 部」大数字，免又像已投产。

### P1（下一迭代）

5. **状态中英双语**  
   表格 `published` 旁加「已发布」，降低非技术观众成本。  

6. **角色权限差异可见**  
   三账号若钱包/项目几乎相同，切换价值弱。建议：李娜侧重应征与译制任务；张总侧重项目与发布；王晓东侧重购额/Key/确认应征。  

7. **网关试调用**  
   选 DeepL/TTS 时禁用「假装走 chat/completions」或明确 mock 分支，避免技术 Lead 抓包质疑。  

8. **需求预算用 T**  
   服务类需求报价用 Tokens 可以，但发行「分账 70/30」不要强行 Tokens 化（v3.3 已分开，保持）。  

9. **对接沙箱**  
   只读：`/api/v1/demands`、`/wallet`；写入：`apply` / `chat/completions`。页头改为「沙箱 API · 非生产」。  

### P2

10. 甘特/PDF/对账等继续延期。  
11. 热度算法四维若要做真，单独立项（平台授权 + 合规），不进中枢 P0。
