## 0. 一句话

> **交付物是「微短剧产业 · AI Agent 工作端」**，不是传统多模块 SaaS 管理后台 / 会员门户平台。  
> 用户主要在 **对话 + 工具调用 + 任务卡片** 里完成工作；悬赏撮合与 Token 托管是 Agent 驱动的**业务能力**，不是另一套「平台网站」主叙事。

---

## 1. 为什么改

| 旧说法 | 问题 |
|--------|------|
| 「会员协作中枢 / SaaS 平台」 | 易做成仪表盘、导航树、多页 CRUD，像通用 B 端后台 |
| TaskMatch 式营销站 | 易做成 Token 市场落地页，偏离工作现场 |
| 目录名 `*-saas` | 仅历史路径，不代表产品形态 |

用户真实场景：在工作现场用 **Agent 协助发单、找人、跟进、验收、查额度**——产品应是**工作端**，不是「再做一个 SaaS」。

---

## 2. 形态定义

### 2.1 是什么

| 层 | 定义 |
|----|------|
| **壳** | AI Agent 工作端（Work Client）：会话为主界面，侧栏/抽屉承载上下文与结果 |
| **脑** | Agent：理解意图 → 调工具 → 回写状态 → 请示关键确认 |
| **手** | 工具/技能：购 T、发悬赏、应征、确认冻结、验收放款、查流水… |
| **账** | 结算与托管规则仍按 MVP / D1.3 / TAX（业务不变，入口变） |

### 2.2 不是什么

- 不是多租户营销型 SaaS 官网当主产品  
- 不是 Web3 任务市场  
- 不是「先做完整后台再挂一个聊天框」  
- 不是取消托管/结算（能力保留，交互改由 Agent 编排）

### 2.3 主界面预算（工作端）

第一屏优先：

1. **Agent 对话区**（主）  
2. **当前任务 / 订单上下文卡**（一份就够）  
3. **关键确认条**（确认接单方、确认验收、确认购 T 等需人点头的动作）  

次级（抽屉或指令唤起，不进永久巨导航）：钱包余额、悬赏大厅列表、流水、开票入口。

**禁止**把 MVP 做成：顶栏一排 SaaS 模块（项目/算力/出海/监督…）当默认壳。

## 3. 与原 MVP 业务的关系

业务闭环**不废**：

```
购 T → 发悬赏 → 应征 → 确认托管冻结 → 验收 → 平台付供应商 T
```

变化的是 **交互载体**：

| 旧（SaaS 页） | 新（Agent 工作端） |
|---------------|-------------------|
| 打开「发布悬赏」表单页 | 对 Agent 说需求 → Agent 填草稿 → 用户确认发布 |
| 大厅点「应征」 | Agent 推荐/列出开放悬赏 → 用户一键应征或口述应征 |
| 确认合作按钮 | Agent 出示应征人对比 → **人工确认** → 触发冻结并播报「已冻结 xxx T」 |
| 验收按钮 | Agent 汇总交付要点 → **人工确认验收** → 播报放款结果 |

人机边界（不可被 Agent 静默跳过）：

- 购 T 扣款确认  
- 确认合作方（冻结）  
- 确认验收（放款）  
- 任何法币/发票提交（后置能力同样要确认）

## 4. 角色在工作端里的默认态

| 角色 | 打开工作端后 Agent 先做什么 |
|------|------------------------------|
| 客户 | 「余额 / 待确认应征 / 待验收」三选一追问；可代拟悬赏 |
| 供应商 | 「今日可接悬赏 / 进行中订单」；可代写应征留言 |
| 平台协助 | 只读查单、催办话术；不做完整监督大盘（MVP） |

登录仍是**机构账号 / 演示切角色**，不是 Connect Wallet。
