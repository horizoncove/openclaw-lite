# 05 · 合规边界与红线（强制）

版本：`minorguard-devdocs-v0.1`  
效力：P3 及后续开发默认遵守；突破需书面变更评审

## 1. 产品合规定位

MinorGuard 是 **授权场景下的未成年人生成式 AI 交互风险识别与分级处置辅助系统**，不是：

- 未经授权的监控软件
- 实名身份认定或处罚系统
- 自动执法/自动报案系统

输出的是风险信号与处置建议；法律后果与平台义务由接入方制度与人类复核共同承担。

## 2. 硬红线（禁止）

```text
✗ 未授权读取第三方 App 私聊、通知、剪贴板
✗ 键盘记录、屏幕抓取、麦克风常开窃听
✗ 绕过平台加密、破解、中间人劫持用户流量
✗ 收集/训练/评测使用真实未成年人私密对话
✗ 在仓库、日志、演示包中明文保存云 API Key 或真实身份证/手机号
✗ 将 minorLikelihood 当作实名年龄认证结果用于处罚
✗ 监管视图默认下发可还原个人身份的原文
✗ 未获监护人/平台/学校明示授权时的大规模采集
```

## 3. 允许的接入方式（白名单）

仅在以下明示授权场景接入：

1. 平台在自有 AI 对话产品内嵌 SDK/API（用户协议披露）
2. 学校/教育机构采购并在校园终端部署
3. 硬件厂商青少年模式/家长控制模块授权集成
4. 企业内部安全评测/红队（合成或员工授权数据）

## 4. 数据处理原则

| 原则 | 落地要求 |
|---|---|
| 最小必要 | 只处理完成风险识别所需文本片段 |
| 目的限定 | 不得挪用于广告画像、信用评分 |
| 脱敏优先 | 台账默认 snippet + 掩码；导出再脱敏 |
| 分级访问 | admin / operator / readonly |
| 可审计 | 读导出清除动作写审计 |
| 可撤回 | 支持按策略删除/匿名化事件（P3 先支持清空与按 id 删的管理接口设计） |

详细字段规则见 `DATA_GOVERNANCE.md`。

## 5. 与中国法治语境的对齐（说明性，非法律意见）

开发时应对齐研究轨已列方向（详见 `docs/minors-ai-protection/` 方案与 `law_mapping_notes`）：

- 《未成年人网络保护条例》等对未成年人网络保护与个人信息保护的要求
- 生成式 AI 服务安全与内容标识相关规范（随政策更新修订本文件）

**本文件不构成律师出具的合规意见。** 试点前需由人类合规/法务确认。

## 6. 模型与外部调用合规

1. 云模型调用可选；默认应可完全本地降级。
2. 发往云端的文本应截断，并尽量避免明文身份信息（检测后掩码再上传为 P3 Should）。
3. 供应商密钥仅环境注入；轮换流程见 `SECURITY_BASELINE.md`。
4. 禁止为「刷红队分数」针对测试集过拟合而牺牲开放域安全性——策略变更必须说明。

## 7. 发布与演示合规检查单

发布/对外演示前：

- [ ] 无真实未成年人 PII 样本
- [ ] 无密钥入库（`git grep` / security-scan）
- [ ] `authRequired` 在对外环境为 true
- [ ] 导出样例经人工抽检无原文隐私
- [ ] README 标明能力边界与「非自动执法」

## 8. 违规升级

发现红线违反：立即停用相关接口 → 吊销密钥 → 清理数据 → 记入审计 → 复盘后再恢复。
