# 01 · PRD：P3 MVP 产品需求

版本：`minorguard-devdocs-v0.1`  
状态：草案待确认

## 1. 产品目标

将 MinorGuard 从「单机可演示样机」升级为「授权场景可部署的 MVP 服务」，使平台/学校/硬件试点方能够：

1. 通过 HTTP API 提交对话文本并获得稳定结构化风险结果；
2. 在权限控制下查询脱敏事件台账与审计日志；
3. 在模型不可用时仍可本地规则降级；
4. 与研究轨端侧小模型（ONNX）预留统一接入口。

## 2. 目标用户与角色

| 角色 | 诉求 | P3 可见能力 |
|---|---|---|
| 平台安全运营 | 看风险事件、处置建议 | 运营只读台账 + 导出 |
| 家长/监护人（间接） | 理解风险与建议 | 仅通过「家长视图摘要」字段，不直连库 |
| 学校信息化/心理支持 | 汇总趋势、脱敏个案 | 聚合统计 + 脱敏详情 |
| 系统管理员 | 配置密钥、重置演示、审计 | Admin API + 审计日志 |
| 研发/红队 | 回归评测 | `save:false` 分析接口 + 红队脚本 |

P3 **不**做完整监护人 App、不做人审工单完整流转（预留状态字段即可）。

## 3. 核心用户故事

1. **作为平台**，我调用 `POST /api/v1/analyze`，获得 `levelCode/actionCode/categories`，以便决定放行或阻断。
2. **作为管理员**，我能开启强制鉴权，使未授权者无法读取事件台账。
3. **作为运营**，我能导出脱敏 Markdown/JSON 报告，且报告不含可识别原文。
4. **作为研发**，我在 DeepSeek 故障时仍能用本地规则完成演示与红队。
5. **作为架构**，我能把研究轨 ONNX 小模型挂到同一分析流水线而不改前端契约。

## 4. 功能范围

### 4.1 Must（P3 必做）

| ID | 能力 |
|---|---|
| F1 | 模块化后端：分析 / 策略 / 事件 / 审计 / 鉴权分离 |
| F2 | 持久化：SQLite（默认）或 PostgreSQL（可选）替代 JSON 文件 |
| F3 | 稳定 API：`/api/v1/*`，兼容 P2 机器码字段 |
| F4 | 鉴权：Admin Token 强制模式 + 角色声明（admin / operator / readonly） |
| F5 | 审计：所有台账读导出清除动作入库 |
| F6 | 分析流水线：local →（可选）cloud LLM →（可选）端侧模型 → policy |
| F7 | 红队回归：不少于现有 30 条；高风险漏报率门禁保留 |
| F8 | 配置与密钥：仅环境变量 / 密钥文件，禁止入库 |
| F9 | 健康检查：版本、策略版本、规则版本、provider、authRequired |

### 4.2 Should（P3 尽量做）

| ID | 能力 |
|---|---|
| F10 | 策略规则外置为 JSON/YAML（只读加载），带 `ruleSetVersion` |
| F11 | 事件筛选：按 levelCode / categoryCode / 时间 |
| F12 | Docker Compose 一键启动（api + db） |

### 4.3 Won’t（明确不做）

- 未授权读取第三方 App 对话、键盘记录、抓屏、流量解密
- 真实未成年人生产数据训练/评测
- 多租户计费、完整 RBAC UI、人审工作流
- 自动报警到执法机关（S4/监管动作保留为后续阶段）
- 将演示包中的 API Key 或真实隐私样本写入仓库

## 5. 成功标准（产品视角）

1. 新同事按文档可在干净环境部署并跑通自测与红队冒烟。
2. 关闭云模型后，本地规则路径仍可通过最小验收。
3. 合规评审能指出「采什么 / 不采什么 / 谁能看」且与实现一致。
4. 研究轨标签结果可通过映射层进入同一 `actionCode` 处置。

## 6. 依赖

- 演示包逻辑基线（本地持有，不强制入库）
- 研究轨 `p0-v1.0` / `p1-v1.0` / `p2-v0.2-tiny`
- DeepSeek 或等价兼容 Chat Completions 接口（可选）
