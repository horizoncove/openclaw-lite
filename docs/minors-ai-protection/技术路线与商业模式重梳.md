# 未成年人端侧 AI 保护系统：技术路线与商业模式重梳

依据全球对标结论重梳。原则：

1. **不硬碰** Apple / Google 已做成的 OS 级裸露检测  
2. **不做** 平台侧 CSAM 哈希赛道（PhotoDNA / Thorn 已占位，且数据红线高）  
3. **主攻** 端侧多轮诱导识别 + 中国法治场景化合规评估 + 可审计分级处置  
4. **商业上** 先卖“合规能力与证据”，再卖“防护效果”

关联文档：
- 研究方案原文
- 逐章全球对标
- 总览对标研究

---

## 一、战略定位（先定边界）

### 1.1 一句话定位

> **面向中国未成年人网络保护合规的端侧风险识别与审计操作系统中间件**  
> （Edge Risk & Compliance Middleware for Minors）

不是又一个家长控制 App，也不是又一个云端内容审核台。

### 1.2 与全球玩家的位置

```text
                    云端/平台侧
                         │
     Thorn Safer ────────┼──────── PhotoDNA
     平台诱拐/CSAM       │         已知哈希
                         │
本地内容防护 ────────────┼──────────── 合规制度
 Apple / Google          │          DSA / OSA / 条例
 裸露模糊/警告           │          风险评估义务
                         │
                    ★ 本项目落点
         端侧多轮诱导 + S0–S4 规则引擎
         + 脱敏审计证据 + 中国标准映射
```

### 1.3 明确不做什么 / 做什么

| 不做（红海或红线） | 做（缺口） |
|---|---|
| 与系统级裸露检测拼精度 | 中文社交诱导多轮识别（端侧） |
| 训练/存储违法与真实未成年私密数据 | 合成数据 + 标签体系 + 评估集 |
| 纯 C 端家长监控 App（先不做） | B2B2C：嵌进 App / 终端 / 未成年人模式 |
| 空泛“AI 治理咨询” | 可运行引擎 + 可导出合规证据包 |

## 二、产品架构（按可变现模块重组）

把原方案 8 个研究目标，收成 **3 层可售产品 + 1 个底座**：

```text
┌─────────────────────────────────────────────┐
│  L3  合规评估与证据层（最先可变现）            │
│  标准映射 / 风险评估报告 / 脱敏审计 / 白皮书   │
├─────────────────────────────────────────────┤
│  L2  策略与处置层（产品差异核心）               │
│  S0–S4 规则引擎 / 可解释原因 / 监护人与复核接口 │
├─────────────────────────────────────────────┤
│  L1  端侧识别层（技术护城河）                   │
│  文本分类 / 图片隐私+OCR / 多轮上下文 / 融合    │
├─────────────────────────────────────────────┤
│  L0  场景与数据底座（研究资产）                 │
│  风险场景库 / 标签体系 / 合成样本 / 评测基准    │
└─────────────────────────────────────────────┘
```

### 模块与全球对标后的优先级

| 优先级 | 模块 | 原因 |
|---|---|---|
| P0 | 场景库 + 标签 + S0–S4 | 所有商业与论文的共同底座；海外难复制中国法规映射 |
| P0 | 端侧文本单句分类 MVP | 最快可演示、可集成；工程路径成熟 |
| P0 | 脱敏审计日志 / 合规报告骨架 | **最先能卖给平台与评估机构** |
| P1 | 多轮 grooming 链路识别 | 全球学术有、端侧系统少；核心技术叙事 |
| P1 | 图片隐私 + OCR（证件/学校/定位/截图） | 避开裸露红海，做未成年人隐私场景 |
| P2 | 多模态融合 + 行为频次/关系特征 | 完整原型差异点 |
| P2 | 终端–App–分发平台联动适配 | 对接未成年人模式生态后放大 |

## 三、重梳后的技术路线

### 3.1 总体路线（由“研究阶段”改为“能力交付阶段”）

```text
阶段 A  标准资产层
  法规场景 → 标签/S0-S4 → 合成数据规范 → 评测集

阶段 B  单模态可部署 MVP
  中文文本端侧分类器 → ONNX/TFLite Demo → 误拦/漏报看板

阶段 C  高价值风险链路
  多轮上下文检测 → 风险趋势分 → 与 S0-S4 绑定

阶段 D  隐私多模态补全
  图片隐私分类 + OCR 规则 → 与文本/多轮融合

阶段 E  合规产品化
  脱敏日志 / 哈希证据 / 合规评估报告 / 试点 SDK
```

与原方案差异：
- **把合规审计前移**，不再放到最后一年才做  
- **多轮识别优先于“大而全多模态”**（对标显示这是更大缺口）  
- **图片先做隐私泄露，不做 CSAM/色情赛道**

### 3.2 推荐技术栈（务实版）

| 层 | 建议选型 | 说明 |
|---|---|---|
| 文本 | TinyBERT / MiniLM / 小参数中文分类模型 → ONNX Runtime / TFLite | 对标已验证可行 |
| 多轮 | 回合级分类器 + 状态机/趋势分；研究期可借鉴 SCoRL 指标，不盲目上重 RL | 端侧先规则+轻模型 |
| 图像 | MobileNetV3 / EfficientNet-lite / MobileViT + 端侧 OCR | 证件、截图、联系方式 |
| 融合 | 分数融合 + 可配置规则引擎（先规则后学习） | 可解释、可审计优先 |
| 审计 | 本地脱敏事件日志 + 内容哈希 + 导出合规包 | 原始内容默认不上传 |
| 集成 | Android/Harmony SDK 优先；iOS 走系统框架互补 | 国内终端生态更贴近 |

### 3.3 端侧部署原则（商业可信的关键）

```text
原始文本/图片默认不出端
仅上传：风险等级、标签、时间戳、内容哈希、模型版本
高风险可选：监护人告警摘要（脱敏）
S3/S4：人工复核工单（平台侧），不回传原文除非授权
```

这是相对 ChildSafe“零数据”宣传、又相对云审核更可落地的折中，也更符合中国平台留痕与处置义务。

### 3.4 里程碑（建议按 12 个月交付重排）

| 时间 | 技术交付 | 可对外演示/销售物 |
|---|---|---|
| 0–2 月 | 场景库 v1、标签 v1、S0–S4、数据合规规范 | 标准说明书、标注指南 |
| 2–4 月 | 文本端侧分类器 + 本地 Demo | App 内拦截 Demo、评测报告 |
| 4–7 月 | 多轮链路检测 + 规则引擎 | grooming 路径演示、处置日志 |
| 5–8 月（并行） | 图片隐私 + OCR | 证件/学校信息风险 Demo |
| 7–10 月 | 多模态融合 v1 | 综合风险等级与可解释原因 |
| 8–12 月 | SDK + 合规证据包 + 试点 | 平台接入包、合规白皮书 |

## 四、商业模式重梳

### 4.1 谁付钱（按付费意愿排序）

全球同类生意（k-ID、年龄核验/合规 SaaS、Thorn、ChildSafe）说明：**付钱的主要是“有合规压力的平台/厂商”，不是孩子本人。**

| 客户 | 付费动机 | 本项目卖点 |
|---|---|---|
| **社交/游戏/内容 App** | 未成年人模式、条例义务、上架审核、舆情风险 | SDK 拦截 + 合规证据 |
| **终端厂商 / OS** | 未成年人模式三方联动、端侧 AI 备案与保护措施 | 系统服务/中间件能力 |
| **分发平台 / 应用商店** | 上架审核、适龄与保护能力核验 | 评估工具与检测报告 |
| **第三方评估 / 律所 / 咨询** | 影响评估、合规审计外包 | 评估指标体系 + 自动化报告 |
| **教育/家校（后期）** | 防护与告警 | 基于已沉淀引擎的轻量方案 |
| C 端家长 App | 付费意愿分散、获客贵 | **不做早期主战场** |

### 4.2 推荐商业模式：双引擎

```text
引擎 A：Compliance-first（合规优先）—— 现金牛入口
引擎 B：Protection-first（防护优先）—— 技术品牌与续费粘性
```

#### 引擎 A：合规即服务（先卖这个）

**产品形态**
- 未成年人网络保护合规评估工具（问卷 + 技术探测 + 报告）
- 风险场景/条款映射库（条例、未成年人模式、AI 未成年人安全指南）
- 脱敏审计与证据包导出（给内审、监管、上架材料）

**收费**
- 年度订阅：按 App/主体数
- 单次评估报告：项目制
- 企业版：多产品线 + 专家复核

**为何先卖它**
- 不依赖模型精度做到极致就能收费  
- 对标 DSA/OSA 催生的合规服务市场逻辑  
- 中国制度压力明确，销售话术清晰  

#### 引擎 B：端侧防护 SDK（后卖这个，但必须做）

**产品形态**
- Edge SDK：文本 / 多轮 / 图片隐私识别  
- Policy Engine：S0–S4 动作配置  
- 监护人/人工复核回调接口  

**收费**
- SDK 授权费（按 DAU 或包年）
- 模型更新与规则库订阅
- 私有化/终端预装（高客单）

**竞争策略**
- 不对标 Apple 裸露检测  
- 主打：中文诱导多轮、隐私图片、可解释分级、可导出合规证据  
- iOS 上与系统 Sensitive Content 能力互补，不重复造轮子  

### 4.3 收入结构建议（成熟期目标画像）

| 收入池 | 占比目标 | 说明 |
|---|---|---|
| 合规评估订阅 / 报告 | 35% | 入口与品牌 |
| SDK / 终端授权 | 40% | 规模化主收 |
| 规则库与模型更新 | 15% | 高毛利续费 |
| 课题/白皮书/标准咨询 | 10% | 学校团队协同，早期重要 |

### 4.4 Go-to-Market（怎么打）

```text
第 1 波：科研样板 + 白皮书
  → 学校法治背书，建立“标准话语权”

第 2 波：2–3 个垂直试点
  → 青少年向社区 / 教育社交 / 轻游戏 / 本地生活未成年人场景
  → 交付：拦截效果 + 合规报告

第 3 波：终端/OS 合作
  → 接入未成年人模式联动
  → 预装或系统服务化

第 4 波：评估机构渠道
  → 把 L3 评估工具卖给第三方审计与上架辅导机构
```

### 4.5 定价逻辑（示意，非最终报价）

| 套餐 | 包含 | 逻辑 |
|---|---|---|
| 评估版 | 条款映射 + 自评估 + 报告 | 低门槛获客 |
| 防护版 | 端侧文本 + 规则引擎 + 审计日志 | 主推中小 App |
| 融合版 | + 多轮 + 图片隐私 OCR | 高风险社交/聊天场景 |
| 终端/平台版 | 私有化、联动未成年人模式、专家规则 | 大客定制 |

## 五、组织分工如何服务商业闭环

| 角色 | 原方案职责 | 重梳后对商业的贡献 |
|---|---|---|
| 学校团队 | 法治、场景、伦理、白皮书 | **引擎 A 的内容生产与背书** |
| 技术团队 | 模型、SDK、原型 | **引擎 B 的交付与壁垒** |
| 联合 | 标签、评测、试点 | 把“论文指标”转成“客户可验收指标” |

建议增设一个轻量 **产品/解决方案角色**（可兼职）：
- 把 S0–S4 翻译成客户配置面板  
- 把合规报告做成可售 SKU  
- 管理试点验收标准（误拦率、召回、时延、证据完整率）

## 六、竞争策略与护城河

### 6.1 护城河优先级

1. **中国法规映射的可计算标签与评估题库**（难被海外 SDK 直接搬）  
2. **合成数据 + 评测基准 + 红队集**（可持续迭代）  
3. **端侧多轮诱导状态机与可解释规则**（工程秘密）  
4. **试点案例与白皮书话语权**（采购信任）  
5. 模型本身（易被追赶，不作为唯一壁垒）

### 6.2 对主要对手的打法

| 对手类型 | 打法 |
|---|---|
| Apple / Google | 互补：他们做裸露，我们做诱导链路与合规证据 |
| Thorn 类平台工具 | 错位：他们服务云端 Trust&Safety，我们服务端侧与中国 App 合规 |
| ChildSafe 类 SDK | 差异：中文场景、条例映射、可验证评测、终端联动 |
| 传统家长控制 App | 不正面竞争获客；必要时后期做 B2B2C 插件 |

## 七、风险与商业约束

| 风险 | 商业影响 | 对策 |
|---|---|---|
| 误拦导致产品体验投诉 | SDK 续费难 | S1 提醒为主，S2+ 可配置；高召回但分级动作克制 |
| 被质疑“监控儿童” | 舆情与采购失败 | 本地优先、最小化上报、对外统一话术 |
| 只有咨询没有产品 | 收入不稳定 | 强制 L3 报告自动化，咨询只作增益 |
| 终端厂商自制 | 大客户流失 | 走“标准+引擎供应商”，可被集成而非替代 OS |
| 数据伦理事故 | 项目毁灭 | 合成数据红线、禁止真实未成年私密与违法材料 |

## 八、对外统一表述（商务 / 申报共用）

**推荐：**
> 我们提供面向未成年人网络保护的端侧风险识别与合规评估能力，帮助应用和终端在本地完成诱导风险识别、分级处置与可审计合规留痕，满足未成年人模式与相关法规要求。

**不推荐：**
> 全球首创儿童监控大模型 / 训练敏感内容模型 / 收集未成年人真实聊天数据。

## 十、结论：现在该怎么排

### 技术上先做
1. 标签 + S0–S4 + 评测集  
2. 端侧中文文本 MVP  
3. 合规证据包骨架  
4. 多轮诱导链路  
5. 图片隐私 OCR  
6. 融合与终端联动  

### 商业上先卖
1. 合规评估与报告（引擎 A）  
2. 垂直 App SDK 试点（引擎 B）  
3. 终端/OS 预装或系统服务  
4. 评估机构渠道分发  

### 成功标准（12 个月）
- 1 套可公开的标签与分级标准  
- 1 个可安装的端侧 Demo（文本+多轮）  
- 1 份可售的合规评估报告模板  
- 2 个以上真实试点接入  
- 1 份白皮书 + 软著/专利布局  

这样，项目不再是“做一个很大的端侧 AI 研究”，而是：

> **用端侧识别能力支撑可售的未成年人保护合规中间件。**
