# 研究方案逐章全球对标

对照文档：`面向未成年人网络保护的端侧AI风险识别与合规评估系统研究方案.md`  
整理日期：2026-08-07

---

## 总判断

全球**没有**与本方案严格同构的公开系统（端侧多模态识别 + grooming 多轮链路 + S0–S4 分级规则引擎 + 法治合规评估白皮书式闭环）。  
但各模块都有明确先例，创新点应写在「一体化」与「中国法治场景化」，不宜写「单项技术全球空白」。

| 本方案模块 | 全球是否已有同类 | 成熟度 | 差异化空间 |
|---|---|---|---|
| 风险场景库 / 标签 | 有 | 高 | 中文场景 + 中国法规映射 |
| S0–S4 分级处置 | 有近似 | 中高 | 可计算、可审计分级标准 |
| 端侧文本分类 | 有 | 高 | 未成年人专项中文小模型 |
| 图片隐私 / OCR | 有 | 高 | 未成年人隐私场景体系化 |
| 多轮 grooming 识别 | 有（多为云/学术） | 中高 | **端侧化**是关键缺口 |
| 多模态融合 + 规则引擎 | 有局部 | 中 | 端侧融合 + 可解释处置 |
| 合规评估 / 脱敏审计 | 有制度、少产品 | 中 | 法学 + 工程双闭环 |
| 完整端侧原型 | 极少完整公开 | 低 | **主创新落点** |

## 二、项目背景：云端滞后 / 隐私 / 缺多轮 / 缺端侧

本方案指出的六类痛点，在全球讨论中高度一致。

| 痛点 | 全球对应现象 | 代表案例 |
|---|---|---|
| 响应滞后 | 平台事后审核、举报驱动 | 传统 Trust & Safety 流水线 |
| 隐私暴露 | 上传聊天/图片到云端审核引发争议 | Apple 曾搁置的 iCloud CSAM 方案争论；端侧成为主流叙事 |
| 缺多轮风险识别 | 单句关键词漏检渐进诱导 | SCoRL、ChatCoder2、Luring Communication Theory |
| 缺端侧即时拦截 | E2EE 下云端不可见 | Apple Communication Safety、Google SafetyCore |
| 缺法治场景化评估 | 法规要求风险评估，技术落地分散 | EU DSA、UK Online Safety Act |
| 缺可解释合规闭环 | 平台有内部审核台，少对公众/监管可解释端侧证据 | Thorn Safer 审核台；ChildSafe.dev 审计日志宣称 |

**对标结论**：问题定义与全球前沿一致，方案成立；创新不在“发现痛点”，而在**如何一体化解决**。

## 三、研究目标（8 项）对标

| # | 本方案目标 | 全球同类 | 是否已被完全覆盖 |
|---|---|---|---|
| 1 | 风险场景库 | NCMEC/IWF 分类、学术 grooming 阶段、中国不良信息审核分类 | 否（缺中国未成年人社交场景化整合库） |
| 2 | 标签与分级标准 | LCT 阶段标签；平台内部 severity；DSA 风险类型 | 否（缺公开 S0–S4 + 处置动作绑定标准） |
| 3 | 端侧文本风险分类 | MiniLM/TinyBERT/MobileBERT 端侧分类；游戏/短信毒性检测 | 部分（通用端侧有，未成年人诱导专项中文端侧少） |
| 4 | 图片隐私风险检测 | Apple/Google 裸露检测；端侧 OCR；证件检测 App | 部分（偏裸露/CSAM，少“证件/学校/定位/截图”未成年人隐私体系） |
| 5 | 多轮对话风险识别 | SCoRL、StagePilot、Thorn Predict 文本诱拐 | 部分（学术与平台侧多，**端侧部署少**） |
| 6 | 风险分级规则引擎 | 平台 policy engine；家长控制规则 | 部分 |
| 7 | 合规评估与脱敏审计 | DSA/OSA 风险评估；DPIA；Safer 报告流 | 部分（制度强、端侧产品弱） |
| 8 | 可演示端侧原型 | Apple/Google 系统能力；ChildSafe SDK；ANIS 原型 | 无完全开源学术样板 |

## 4.1 风险场景体系

本方案场景：

```text
陌生人搭讪 / 年龄试探 / 隐私索取 / 照片诱导 / 线下见面
礼物交换 / 网络欺凌 / 情感操控 / 胁迫威胁 / 个信泄露 / 平台治理失效
```

| 全球对照 | 说明 | 相似度 |
|---|---|---|
| Luring Communication Theory（LCT） | 诱拐分阶段：个人信息交换→建立信任→评估风险→性剥削准备 | 高（理论基础） |
| ChatCoder2 标注体系 | 回合级诱拐策略标签 | 高 |
| Thorn Safer Predict 标签 | 交易 nudes、诱拐、幻想/角色扮演等 | 高（偏 CSE） |
| T/AII 002-2021 | 未成年人主体敏感 + 不宜内容细分 | 高（国内标准） |
| 中国未成年人模式相关指南 | 内容、时长、功能、适龄 | 中（偏产品模式，非对话诱导细分类） |

**差异化建议**：把「平台治理失效」与「法治场景」显式入库，是相对海外诱拐数据集的增量；同时应主动引用 LCT/ChatCoder2，避免被审稿人指“忽视既有分类学”。

---

## 4.2 风险标签与 S0–S4 分级

| 本方案设计 | 全球近似 | 差异 |
|---|---|---|
| S0 允许 / S1 提醒 / S2 阻止 / S3 复核告警 / S4 合规流程 | Apple：模糊+警告+可信成人；平台：allow/limit/block/report；执法上报 | 本方案把处置动作与等级一一绑定，并预留合规流程档 |
| `age_probe` 等细标签 | LCT 阶段标签；Safer 文本分类标签 | 标签更偏“未成年人社交诱导全链路”，不止 CSAM |
| `grooming_sequence` | 学术 turn-level / stage-level 标签 | 名称与目标一致，应做成序列标签而非单句标签 |

**结论**：分级思想不新，但**公开、可复用、面向端侧动作的 S0–S4 标准**仍有标准制定空间。

---

## 4.3 端侧文本风险分类模型

候选 MiniLM / DistilBERT / TinyBERT / MacBERT-small：技术路线成熟。

| 全球实践 | 内容 | 与本方案关系 |
|---|---|---|
| MobileBERT / TinyBERT 端侧部署 | TFLite/ONNX/INT8，手机可实时推理 | 直接可借鉴工程路径 |
| 端侧短信/通知分类（如 NotifAI） | DistilBERT/MobileBERT 本地分类 | 证明端侧文本分类可行 |
| 游戏聊天 TinyBERT 毒性检测 | 端侧/近端毒性分类 | 场景近，但非未成年人诱导 |
| Apple/Google 系统级模型 | 闭源端侧 ML | 产品级标杆，不可复现细节 |

**缺口**：公开工作多为英语毒性/垃圾短信/情感；**中文未成年人诱导（年龄试探、线下约见、礼物换照片）端侧分类器**较少见。  
**建议**：MVP 优先 TinyBERT/MiniLM + 中文合成数据；评测强调高风险高召回与误拦率。

---

## 4.4 图片隐私风险检测

| 检测方向 | 全球同类 | 成熟度 |
|---|---|---|
| 裸露/敏感画面 | Apple Communication Safety；Google SafetyCore；Sensitive Content Analysis API | 很高 |
| 证件/联系方式/OCR | 端侧 OCR（ML Kit 等）+ 规则；隐私相册类 App | 高 |
| 学校信息 / 聊天截图 / 自拍风险 | 分散能力，少成体系未成年人隐私风险库 | 中低 |
| CSAM 哈希 | PhotoDNA、PDQ；多为平台侧 | 高（但本方案明确禁止违法材料训练，应只作边界说明） |

**本方案特点**：强调“隐私泄露型图片风险”，而非只做色情/CSAM。这与 Apple/Google 的敏感内容警告部分重叠，但**证件、学校、定位、截图**组合更贴近未成年人社交诱导场景，可写成差异点。

## 4.5 多轮对话风险识别（关键创新点）

这是本方案技术含量最高、也最需谨慎表述的部分。

| 全球研究/系统 | 形态 | 与本方案对照 |
|---|---|---|
| **SCoRL（NAACL 2025）** | 回合级风险标签 + 强化学习控制“尽早干预” | 高度同题：多轮诱拐早期识别 |
| **StagePilot（2026）** | 阶段策略模拟 cybergrooming 长对话 | 同题：阶段链路建模；可用于合成数据 |
| **ChatCoder2 / LCT** | 诱拐阶段与回合策略标注 | 标签与链路设计应兼容 |
| **Thorn Safer Predict** | 平台侧文本诱拐/CSE 分类 | 能力近，部署在服务端 |
| **AIOpenSec Guardian** | 端侧行为路径，不读原文 | 端侧隐私路径不同：行为 vs 内容 |
| **ChildSafe.dev** | 宣称端侧文本威胁检测 | 产品叙事接近，公开评测有限 |

**关键判断**：
- “多轮 grooming 识别”在学术与平台侧**不是空白**；
- **把它做成端侧、可解释、与 S0–S4 处置绑定的系统**，公开完整方案仍少；
- 立项表述建议改为：  
  > 针对既有多轮诱拐检测多部署于云端/研究环境的现状，本项目研究面向边缘设备的轻量化多轮风险识别与分级处置机制。

## 4.6 端侧多模态融合

| 融合信号 | 全球近似 |
|---|---|
| 文本 + 图像 | Apple/Google 偏图像；ChildSafe 宣称文本+图像；ANIS 视觉+OCR |
| OCR 风险分 | ML Kit OCR + 规则早退（ANIS） |
| 对话历史 / 关系 / 频次 | Guardian 行为路径；平台图特征；学术 conversation-level 特征 |

**缺口**：公开系统很少同时在端侧融合  
`文本 + 图片 + OCR + 多轮历史 + 关系/频次 → 综合等级 + 可解释原因 + 处置动作`。  
这是架构创新点，宜作为原型系统主演示链路。

## 4.7 AI 治理与合规评估

| 本方案关注点 | 全球/国内对照 |
|---|---|
| 数据最小化 / 脱敏 | GDPR、Children's Code、个保法、未成年人条例 |
| 监护人告警 | Family Link、Screen Time、未成年人模式 |
| 人工复核 | Trust & Safety 人审；Safer 审核台 |
| 平台责任边界 | DSA、OSA、中国平台义务条款 |
| 算法可解释 / 误判责任 | 欧美 AI 治理讨论；国内 AI 未成年人安全指南（国标计划） |
| 合规评估指标体系 | DSA/OSA 儿童风险评估；DPIA；国内影响评估要求 |

**差异化**：海外多为“平台合规义务文档”；本方案要把合规做成与端侧系统联动的**评估指标 + 脱敏审计 + 政策建议**，属于交叉学科增量，不是纯算法首创。

## 五、技术架构五层对标

```text
输入层 -> 模型层 -> 融合层 -> 动作层 -> 审计层
```

| 层级 | 已有全球系统 | 本方案增量 |
|---|---|---|
| 输入层 | 各 IM/OS 已具备 | 统一未成年人风险输入规范 |
| 模型层 | 端侧小模型、OCR、诱拐分类分散存在 | 未成年人专项模型组合 |
| 融合层 | 平台 policy 引擎为主 | 端侧融合 + 规则引擎 |
| 动作层 | 提醒/模糊/阻止/家长控制 | S0–S4 标准化动作 |
| 审计层 | 平台报告、部分 SDK 日志 | 脱敏日志 + 哈希证据 + 合规报告 |

**最接近的产品拼图**：
1. Apple/Google（动作层图像防护）  
2. ChildSafe.dev（端侧 + 审计叙事）  
3. Thorn Safer（诱拐文本 + 合规报告，但非端侧）  
4. SCoRL/StagePilot（多轮学术方法）  
5. 中国未成年人模式 + AI 未成年人安全指南（法治底座）

## 六、数据方案对标

本方案“合成优先、禁止真实未成年人私密/违法材料”与国际伦理共识一致。

| 做法 | 全球对照 | 评价 |
|---|---|---|
| LLM 合成 + 人工审核 | StagePilot 等用 LLM 模拟诱拐对话；安全研究常用合成 | 正确且必要 |
| 公开安全研究数据集 | ChatCoder2 等（需严格许可与伦理审查） | 可用于方法对比，慎用于直接训练 |
| 禁止真实未成年私密数据 | 各伦理委员会 / 平台政策普遍要求 | 对外表述优势 |
| MVP 规模（3k 文本 / 500 多轮 / 1k 图） | 对 Demo 合理；对稳健泛化偏小 | 适合阶段二，后续需扩增与对抗集 |

## 七、实施计划可行性（对照全球成熟路径）

| 阶段 | 建议对标里程碑 | 风险 |
|---|---|---|
| 阶段一 标签体系 | 对齐 LCT + 国内条例/团体标准 | 标签过细导致标注成本爆炸 |
| 阶段二 文本 MVP | TinyBERT/MiniLM ONNX/TFLite Demo | 中文诱导样本覆盖不足 |
| 阶段三 图片+OCR | MobileNet/MobileViT + 端侧 OCR | 与 Apple/Google 比精度落差需管理预期 |
| 阶段四 多轮+融合 | 借鉴 SCoRL 回合级指标；端侧上下文窗口裁剪 | 端侧算力与上下文长度矛盾 |
| 阶段五 合规+原型 | 对齐 DSA/OSA 评估结构 + 国内白皮书体例 | 法学产出与工程原型节奏不一致 |

## 可直接写入立项书的“国内外现状”段落

经梳理，国际上已在操作系统层部署端侧敏感内容识别（Apple Communication Safety、Google SafetyCore），在平台 Trust & Safety 层形成 CSAM/诱拐检测与报告工具（Microsoft PhotoDNA、Thorn Safer），在学术层开展多轮性诱拐早期识别与阶段建模（基于 LCT/ChatCoder2 的 SCoRL、StagePilot 等），并在商业层出现端侧儿童安全 SDK 叙事（ChildSafe.dev）。与此同时，欧盟 DSA、英国 Online Safety Act 等推动平台开展儿童风险评估，中国则通过《未成年人网络保护条例》、未成年人模式技术要求及人工智能涉及未成年人应用安全指南等构建制度基础。

总体看，全球在“端侧图像敏感内容防护”“平台侧诱拐/CSAM 检测”“多轮诱拐学术识别”“法规驱动合规评估”等方向均有积累，但将中文未成年人社交诱导场景、端侧轻量化多模态与多轮识别、S0–S4 可解释分级处置、脱敏审计及法治合规评估集成为统一可演示系统的公开方案仍较少见。本项目面向这一整合缺口开展研究。

## 建议立即补强的对标动作

1. **文献**：SCoRL（NAACL 2025）、StagePilot、LCT、ChatCoder2、端侧 TinyBERT/MobileBERT 部署论文。  
2. **产品**：Apple / Google 端侧能力边界说明；ChildSafe.dev 功能清单（标注“宣传口径，待验证”）。  
3. **标准**：T/AII 002-2021、未成年人模式技术要求、TC260 AI 未成年人安全指南。  
4. **表述**：创新点统一改成“端侧一体化 + 中国法治场景化”，避免“全球首创多轮诱拐识别”。
