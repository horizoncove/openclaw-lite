# MVP 与 P0–P10 技术路线细案

在《技术路线与商业模式重梳》基础上，把系统拆到可排期、可验收、可砍范围的粒度。

核心原则：

1. **MVP 只证明一件事**：端侧能对中文诱导风险做分级处置，并留下可审计脱敏证据  
2. **P0–P3 构成可试点产品**；P4–P7 构成完整技术壁垒；P8–P10 构成生态放大与商业规模化  
3. 每一级都写清：做什么 / 不做什么 / 验收标准 / 依赖 / 产出物

---

## 0. 总览

```text
P0  场景·标签·分级底座
P1  合成数据与评测基准
P2  端侧文本单句分类器
P3  S0–S4 规则引擎 + 脱敏审计     ← MVP = P0~P3 最小闭环
──────────── 可对外试点分界线 ────────────
P4  多轮诱导链路识别
P5  图片隐私 + OCR
P6  多模态融合与可解释输出
P7  SDK 化与端侧性能工程
──────────── 可规模售卖分界线 ────────────
P8  合规评估报告产品化
P9  未成年人模式 / 终端·分发联动
P10 红队对抗、持续学习与运营中台
```

| 层级 | 名称 | 目标状态 | 建议周期 |
|---|---|---|---|
| **MVP** | 端侧文本风险分级 + 证据闭环 | 可演示、可接入实验 App | 10–14 周 |
| P0–P3 | MVP 组成项 | 试点就绪 | 含在 MVP 内 |
| P4–P7 | 完整防护引擎 | 可售 SDK | MVP 后 4–6 月 |
| P8–P10 | 合规产品与生态 | 可规模化经营 | 并行/后续 3–6 月 |

## 1. MVP 定义（先钉死）

### 1.1 MVP 一句话

> 在 Android / Harmony 演示 App 中，对中文单句与短上下文聊天进行本地风险分类，按 S0–S2（可演示到 S3 告警）处置，并导出不含原文的脱敏审计包。

### 1.2 MVP 必须有

```text
1. 风险标签子集（至少 8 个高频标签）
2. S0–S4 定义（MVP 先落地 S0/S1/S2，S3 用本地告警模拟）
3. 端侧文本分类模型（ONNX/TFLite）
4. 本地推理 Demo（输入文本 → 标签+等级+原因 → 允许/提醒/阻止）
5. 脱敏事件日志（等级、标签、哈希、模型版本、时间戳）
6. 一键导出“合规证据包”（JSON/PDF 简报）
7. 离线评测集与基础指标看板（精准/召回/误拦/时延）
```

### 1.3 MVP 明确不做

```text
✗ 多轮完整 grooming 状态机（放到 P4）
✗ 图片/OCR（放到 P5）
✗ 真实未成年人数据
✗ iOS 完整适配（可后置；先 Android/Harmony）
✗ 云端审核台 / 人审工作流完整版（P3 仅留接口）
✗ 监护人 App
✗ 与应用商店正式联调
✗ 语音输入（可用外部 ASR 文本代替，不自研）
```

### 1.4 MVP 验收标准（建议写进试点合同）

| 指标 | 目标 |
|---|---|
| 端侧包体（模型+规则） | ≤ 40MB（争取 ≤ 25MB） |
| 单句推理 P95 | ≤ 80ms（中端机） |
| 高风险标签召回（评测集） | ≥ 0.85 |
| 正常样本误拦率（S2 及以上） | ≤ 3% |
| 证据包可复现 | 同输入 → 同等级/同模型版本可追溯 |
| 离线可用 | 无网可完成识别与本地日志 |

### 1.5 MVP 演示剧本（对外只讲这 4 个）

1. **年龄试探**：提醒（S1）  
2. **索要微信/学校**：阻止发送（S2）+ 解释原因  
3. **线下见面诱导**：阻止（S2）并生成告警事件（S3 模拟）  
4. **正常同学聊天**：放行（S0），证明低误拦

## 2. P0–P10 详细拆解

---

### P0｜场景·标签·分级底座

**目标**：把“什么算风险、怎么处置”变成机器可执行规范。

**做什么**
- 梳理法规/案例 → 场景分类表（陌生人搭讪、年龄试探、隐私索取等）
- 发布标签字典 v1（英文 key + 中文定义 + 正负例）
- 定义 S0–S4 与默认动作、升级条件
- 建立标签 ↔ 条例/未成年人模式条款映射表（哪怕先 20 条）

**MVP 标签子集（建议先做这 8 个）**

```text
age_probe
privacy_request
contact_request
school_request
photo_request
offline_meeting
emotional_manipulation
threat
```

其余（`gift_exchange`、`grooming_sequence`、`help_request` 等）P4 再加重。

**不做什么**
- 不追求一次覆盖全部长尾标签
- 不在本阶段训练模型

**验收**
- 《标签与分级规范 v1.0》评审通过
- 每个标签 ≥ 20 条正例定义说明
- S0–S4 决策表可被规则引擎直接编码

**产出**
- 场景库 v1
- 标签体系 v1
- S0–S4 规范 v1
- 条款映射表 v0.1

**依赖**：无（启动项）

---

### P1｜合成数据与评测基准

**目标**：在合规红线下，做出可训练、可回归的数据资产。

**做什么**
- 合成数据生成流水线（模板 + LLM 辅助 + 人工审核）
- 单句训练集：建议 ≥ 3000（MVP 可先 1500，但要类别均衡）
- 评测集：≥ 500，独立于训练，含对抗改写
- 拒绝/保护话术库：≥ 200（用于 S1/S2 提示文案）
- 数据卡（Data Card）：来源、审核人、禁用规则、版本

**数据红线（强制）**

```text
允许：合成、公开安全研究许可数据、授权脱敏、安全替代图
禁止：真实未成年私密、违法材料、未授权平台抓取、可识别敏感原文长期存储
```

**不做什么**
- 不引入真实聊天导出“增准”
- 不做图片大数据（P5 再开）

**验收**
- 训练/验证/测试严格隔离
- 每个 MVP 标签在测试集 ≥ 40 条
- 人工抽检通过率 ≥ 95%（标签正确性）

**产出**
- 数据集 v1 + 生成工具
- 评测基准 v1
- 《数据合规规范 v1》

**依赖**：P0

---

### P2｜端侧文本单句分类器

**目标**：本地跑通“文本 → 多标签/多类风险 → 分数”。

**做什么**
- 选型：TinyBERT / MiniLM / 小参数中文分类模型
- 多标签或层次分类（先多标签 sigmoid 更贴合）
- 导出 ONNX 或 TFLite；INT8/FP16 量化
- Android/Harmony Demo App：输入框 + 结果面板
- 基础可解释：Top 标签、关键词高亮或规则命中说明（可先规则辅助）

**模型目标（MVP）**

| 项 | 目标 |
|---|---|
| 类别 | MVP 8 标签 + `normal` |
| 体积 | ≤ 30MB |
| P95 时延 | ≤ 80ms |
| 宏平均 F1 | ≥ 0.80（争取 0.85） |
| 高风险三类召回（contact/offline/threat） | ≥ 0.90 |

**不做什么**
- 不上大模型端侧生成式审核
- 不做多轮（P4）
- 不追求超越云端大模型绝对精度

**验收**
- 无网推理成功
- 评测脚本一键产出报告
- Demo 可录屏演示 4 个剧本

**产出**
- `text-risk-classifier` 模型包
- 本地 Demo
- 《文本风险评估报告 v1》

**依赖**：P0、P1

---

### P3｜S0–S4 规则引擎 + 脱敏审计（MVP 闭环完成）

**目标**：把模型分数变成“可配置处置 + 可导出证据”。

**做什么**
- 规则引擎：
  - 输入：标签分数、简单上下文计数（如 5 分钟内同类命中次数）
  - 输出：S0–S4、动作、对用户提示文案、原因码
- 默认策略：
  - S0 放行
  - S1 提醒可继续
  - S2 阻止发送
  - S3 本地告警事件（完整监护人推送可后置）
  - S4 仅预留接口（合规流程，不在 MVP 自动触发）
- 审计：
  - 记录：`event_id, ts, labels, scores, level, action, content_hash, model_ver, rule_ver`
  - **不记录原文**
- 证据包导出：JSON + 一页 PDF 摘要（命中分布、版本、样本哈希列表）

**不做什么**
- 不做完整人审后台
- 不做云端原文取证
- 不做复杂 AB 实验平台

**验收**
- 同一输入在相同版本下等级稳定
- 修改规则版本可在证据包中体现
- 抽检 100 条：无原文落盘

**产出**
- Policy Engine v1
- Audit Exporter v1
- 合规证据包样例

**依赖**：P2  
**至此 = MVP 完成**

---

### P4｜多轮诱导链路识别

**目标**：识别“渐进升级”，而不是只抓单句脏词。

**做什么**
- 会话状态：滑动窗口（如最近 8–20 轮）
- 回合级标签累积 → 路径分（path score）
- 典型状态机：
  ```text
  普通 → 年龄试探 → 隐私索取 → 要照片
  陪伴安慰 → 情感依赖 → 操控 → 线下见面
  礼物承诺 → 交换照片 → 保密要求
  ```
- 新增标签：`grooming_sequence`、`gift_exchange`、`help_request`（可选）
- 指标：尽早干预回合数、路径召回、过早误报率（对齐 SCoRL 思路，端侧用轻量实现）

**技术策略（务实）**
- v1：单句模型 + 状态机/积分规则（先上线）
- v2：轻量序列编码器或回合级分类器
- 不把重型 RL 作为上线前提

**不做什么**
- 不上云端长上下文大模型做主路径
- 不实时上传对话全文

**验收**
- 至少 3 条标准诱导路径可在第 N 轮前触发 S2（N 可配置，默认 ≤ 6）
- 正常闲聊长会话误升至 S2 的比例 ≤ 2%
- 端侧额外内存增量可控（目标 ≤ 50MB）

**产出**
- Dialogue Risk Module v1
- 多轮评测集（≥ 500 组中的第一批 ≥ 150 组）
- 路径可视化 Demo

**依赖**：MVP（P0–P3）

---

### P5｜图片隐私风险 + OCR

**目标**：补齐“发图泄密/诱导要图”侧能力，避开裸露检测红海。

**做什么**
- 图像类别（先 5–7 类）：
  ```text
  id_document
  school_info
  contact_info_in_image
  geo_location_clue
  chat_screenshot
  selfie_risk_context   # 谨慎定义，不做色情检测口号
  other_safe
  ```
- 端侧 OCR + 规则：手机号、微信号、地址、学校名、身份证号模式
- 与文本联动：`photo_request` + 即将发送图片 → 抬升等级
- 模型：MobileNetV3 / EfficientNet-lite / MobileViT + OCR 引擎

**不做什么**
- 不做 CSAM/裸露专用模型宣传与训练
- 不建立违法图像库
- 不与 Apple/Google 敏感内容框架拼裸露精度（iOS 可调用系统能力作补充）

**验收**
- 证件/含联系方式截图召回 ≥ 0.90
- OCR 规则误报可配置白名单
- 端侧总包体仍可接受（建议图像模型单独 ≤ 20MB）

**产出**
- Image Privacy Module v1
- OCR Rule Pack v1
- 《图片隐私风险评估报告》

**依赖**：P0、P3（等级联动）；可与 P4 并行

---

### P6｜多模态融合与可解释输出

**目标**：统一分数、统一原因、统一动作。

**做什么**
- 融合输入：
  ```text
  文本分、多轮路径分、图像分、OCR 分、
  频次特征、关系特征（是否陌生人/新会话）
  ```
- 融合策略：
  - v1：加权 + 规则优先级（可解释）
  - v2：小模型校准层（可选）
- 输出结构标准化：
  ```json
  {
    "level": "S2",
    "action": "block",
    "labels": ["privacy_request", "contact_request"],
    "reasons": ["索取联系方式", "会话内重复试探"],
    "scores": {"text": 0.91, "dialogue": 0.74}
  }
  ```
- 用户侧解释文案 + 开发者侧原因码

**不做什么**
- 不做黑盒端到端大一统网络替代规则
- 不做无法向客户解释的隐式处置

**验收**
- 融合后高风险召回不低于单模态最好值
- 每个 S2+ 事件必须有 ≥ 1 条可读原因
- 规则/权重变更可版本化

**产出**
- Fusion Engine v1
- Reason Code 字典
- 综合风险 Demo

**依赖**：P4、P5（P5 可先用 OCR 规则弱融合）

---

### P7｜SDK 化与端侧性能工程

**目标**：从 Demo 变成可集成产品。

**做什么**
- SDK API：
  - `analyzeText()`
  - `analyzeImage()`
  - `analyzeSessionTurn()`
  - `exportAuditPack()`
  - `updatePolicy()`
- 性能：冷启动、内存、耗电、并发、机型矩阵
- 模型热更新通道（规则包优先热更；模型次之）
- 集成样例：IM 发送链路拦截、相册发送前检查
- 文档：接入指南、隐私说明、版本兼容

**验收**
- 第三方工程 1 日内完成基础接入
- 中端机内存峰值文档化
- 崩溃率/ANR 有基线

**产出**
- Edge SDK v1（Android/Harmony；iOS 后续）
- 接入样例工程
- 性能基准报告

**依赖**：P6（可先对 P3 文本能力做 SDK alpha）

---

### P8｜合规评估报告产品化（引擎 A 变现）

**目标**：把研究能力变成可售“合规评估 SKU”。

**做什么**
- 评估问卷 + 技术探测清单（是否有端侧拦截、日志、适龄提示等）
- 条款映射自动打分（条例 / 未成年人模式 / AI 未成年人安全指南）
- 生成：
  - 合规差距清单
  - 风险场景覆盖率
  - 证据包完整性评分
  - 整改建议
- 面向评估机构的白牌报告模板

**不做什么**
- 不把自己包装成行政机关
- 不承诺“免责”“替代监管审批”

**验收**
- 对 1 个真实/模拟 App 产出完整报告 ≤ 3 个工作日
- 报告章节稳定可复用

**产出**
- Compliance Reporter v1
- 报告模板与评分卡
- 销售演示材料

**依赖**：P0 映射表 + P3 证据包；可与 P4–P7 并行推进

---

### P9｜未成年人模式 / 终端·分发联动

**目标**：进入系统生态，而不是永远做 App 内嵌套件。

**做什么**
- 对接终端未成年人模式状态（开启/年龄段）
- App 随系统模式自动切换策略包（更严阈值/更强提示）
- 为分发平台提供“保护能力声明 + 检测结果”材料接口
- 预留监护人验证/时长策略联动（调用系统能力，不自建账号体系）

**不做什么**
- 不自研全套家长控制 OS
- 不取代厂商未成年人模式，只做增强引擎

**验收**
- 在至少 1 个终端环境完成模式感知与策略切换 Demo
- 输出给分发平台的材料包格式稳定

**产出**
- Mode Adapter v1
- 终端/分发合作说明
- 联动时序图与接口文档

**依赖**：P7；商务上依赖厂商/平台试点

---

### P10｜红队对抗、持续学习与运营中台

**目标**：长期可用，不被绕过和误伤拖死。

**做什么**
- 红队集：谐音、拆字、表情、隐语、图片绕过、多轮慢诱导
- 误拦申诉与规则回滚机制
- 指标运营看板：召回、误拦、时延、S 级分布、版本对比
- 安全运营：模型投毒防护、规则包签名、更新审计
- 持续学习闭环：仅用合成/授权/申诉脱敏特征更新，不回流原文

**不做什么**
- 不搞“自动抓取全网真实未成年对话”优化模型
- 不把运营中台做成监控儿童的云端窃听系统

**验收**
- 每版本发布附红队回归报告
- 重大误拦可在 24h 内通过规则热更缓解
- 更新链路有签名与审计

**产出**
- Red Team Bench v1
- Ops Console v1（可先内部）
- 发布与回滚手册

**依赖**：P7、P8；贯穿后期全生命周期

## 4. 人员与节奏建议（对应 P 级）

| 阶段 | 主要人力 | 焦点 |
|---|---|---|
| P0–P1 | 法学/标注 + 数据工程 | 标准与数据 |
| P2–P3 | 模型 + 端侧工程 | **打出 MVP** |
| P4–P6 | NLP/多模态 + 规则 | 能力完整化 |
| P7 | 客户端 SDK 工程 | 可集成 |
| P8 | 法学 + 产品 | **开始变现** |

| P10 | 算法运营 + 安全 | 持续迭代 |

建议编制（小团队最小集）：
- 算法 2（文本/多轮、图像 OCR）
- 端侧工程 1–2
- 数据与标注 1（可兼）
- 法学/合规 1（学校侧）
- 产品/解决方案 0.5–1

## 5. 每级“完成定义”清单（DoD）

| 级别 | Done 意味着 |
|---|---|
| P0 | 标签/分级可被代码直接使用，不再靠口头约定 |
| P1 | 有可复现训练与评测数据版本 |
| P2 | 无网 Demo 跑通，指标达标 |
| P3 | 能导出无原文证据包，MVP 可对外演示 |
| P4 | 能演示至少 3 条诱导升级被提前阻断 |
| P5 | 发图场景能拦证件/联系方式类隐私 |
| P6 | 任意 S2+ 都有统一结构化解释 |
| P7 | 外部团队可按文档接入 SDK |
| P8 | 能卖出/交付一份合规评估报告 |
| P9 | 系统未成年人模式切换可演示 |
| P10 | 发版具备红队回归与热更回滚 |

## 6. MVP 之后的两条并行轨道

全球对标后的最佳执行方式不是“串到 P10 才卖”，而是：

```text
轨道 1（防护）：P4 → P5 → P6 → P7 → P9
轨道 2（合规）：P8（基于 P0+P3 立即启动）→ P10 运营化
```

- **轨道 2 负责现金流与课题话语权**  
- **轨道 1 负责技术壁垒与 SDK 溢价**

## 8. 一页纸执行版

**MVP（P0–P3）**  
场景标签 → 合成评测数据 → 端侧文本分类 → 规则分级 + 脱敏证据包

**增强（P4–P7）**  
多轮诱导 → 图片隐私 OCR → 融合解释 → SDK 性能工程

**放大（P8–P10）**  
合规报告产品化 → 未成年人模式/终端联动 → 红队与运营中台

**成功口令**  
先闭环，再多轮，再多模态，先证据，再生态。
